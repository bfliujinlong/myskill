## 7. 服务完成标准与交付物

**7.1 验收标准**（≥5 条，核心四条不可省）
1. 提交各阶段交付物
2. **不以人天签到或出勤为依据**
3. 以《迁移系统范围清单（调研确认版）》+ 各阶段交付物 + **迁移完成的系统数量**为准
4. 每套系统须：迁移验证 + 数据完整性确认 + 功能验证通过 + 双方确认割接完成 + 无因迁移造成的重大业务影响
5. 各模块**分别验收、互不依赖**
6. 阶段交付物经甲方书面/在线确认即视为该阶段验收通过

## 附录 E AWS 专有口径

**E.1 目标端平台基线**（专有服务名按官方写法，一律英文）
- 账号与治理：`AWS Organizations` / `Control Tower` / `IAM` / `CloudTrail` / `Config` / `Service Control Policy`
- 网络：`VPC` / `Transit Gateway` / `Direct Connect` / `ALB`/`NLB` / `NAT Gateway` / `Site-to-Site VPN`
- 计算存储：`EC2` / `EKS` / `S3` / `EFS` / `EBS` / `AMI`
- 数据库与数据：`RDS` / `Aurora` / `DMS` / `Redshift` / `Glue` / `EMR`
- 安全：`Security Hub` / `GuardDuty` / `WAF` / `KMS` / `Shield`
- 可观测：`CloudWatch` / `CloudTrail` / `X-Ray`

**E.2 方法论口径**
- 迁移策略按 **6R**（Rehost / Replatform / Repurchase / Retain / Retire / Refactor）逐系统定级
- 评估框架引用 **AWS CAF**（Cloud Adoption Framework）六视角；架构评审引用 **Well-Architected Framework** 六大支柱
- 迁移节奏按 **Migration Wave** 分批，每 wave 单列切割计划与回退方案

**E.3 验收口径（AWS 项目常见）**
- Landing Zone 基线以双方确认的 Control Tower / Organizations 配置为准
- Well-Architected 评审结论作为架构验收参考项，不作商务罚金依据
- 专有名词不翻译：EC2 / S3 / VPC / IAM / DMS / EKS / Control Tower

**E.4 商务口径**
- AWS 资源费用（含 Savings Plans / RI / EDP）由甲方与 AWS 侧结算，不在本 SOW 服务金额内
