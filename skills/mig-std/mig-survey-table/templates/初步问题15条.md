## 一、LZ 架构 / IaC（1–5）

**Q1. IaC 代码库治理 / IaC repo governance**
- 中：IaC（Terraform/CDK）代码库的版本管理、评审和移交要求是什么？是否有代码结构、命名规范或 CI/CD 流水线的具体标准？
- EN: What are the versioning, review, and handover requirements for IaC (Terraform/CDK) repositories? Are there specific standards for code structure, naming conventions, or CI/CD pipelines for IaC?
- **阻塞级别**：高（决定 LZ 交付物验收标准与 IaC 人天系数）

**Q2. 是否已有 LZ 模板 / Existing LZ template?**
- 中：Landing Zone 架构是否有已有模板或参考架构？还是需要从零设计？现有全球 LZ 标准是否适用于中国区？
- EN: Does the customer have an existing LZ template or reference architecture? Or is this a greenfield design? Do global LZ standards apply to China regions?
- **阻塞级别**：高（绿地 vs 复用，直接决定 LZ 工作量档位）

**Q3. 两套 LZ 的账户组织边界 / Account org & isolation boundary**
- 中：两套 Landing Zone 是否共用同一云账户组织？还是完全独立的组织架构？隔离边界如何划定？
- EN: Will the two Landing Zones share the same cloud account organization, or are they fully independent? How is the isolation boundary defined?
- **阻塞级别**：高（影响 LZ 套数、网络互联、成本归集）

**Q4. 商务协议与采购责任 / Contract & procurement ownership**
- 中：客户是否已签署中国公有云（阿里云）的企业协议，及商务前期工作是否完成？供应商是否需要协助采购或仅负责技术部署？
- EN: Has the customer already signed an enterprise agreement with a China public cloud (Alibaba Cloud)? Must the vendor assist procurement or only handle technical deployment?
- **阻塞级别**：中（影响开工前提与是否含采购支持工作量）

**Q5. DR Region 要求与 RTO/RPO / DR pilot-light & RTO/RPO**
- 中：DR Region 的 pilot-light 要求中，哪些工作负载是强制要求跨区复制的？RTO/RPO 目标是多少？
- EN: For the pilot-light DR Region, which workloads are mandatorily required for cross-region replication? What are the RTO/RPO targets?
- **阻塞级别**：**极高**（历史阻塞项；未确认不得出报价/SOW 终版）

## 二、迁移范围（6–10）

**Q6. 迁移波次与依赖 / Wave plan & dependency map**
- 中：各部分的迁移波次如何划分？目前是否已有迁移波次计划或依赖关系图？
- EN: How will migration waves be structured? Is there an existing wave plan or dependency map?
- **阻塞级别**：高（决定 HyperCare 期数、实施排期）

**Q7. Lift & Shift 可行性（EOL）/ Lift-and-shift feasibility**
- 中：迁移方式被标注为 "Lift and Shift"，但 IT 架构（OS 版本、数据库版本）是否已过可行性评估？是否存在 EOL 操作系统？
- EN: Migration is labeled "Lift and Shift" — has a feasibility assessment been conducted for OS/DB versions? Are there any EOL operating systems?
- **阻塞级别**：高（EOL → 6R 由 Rehost 改 Replatform，工时重算）

**Q8. CI/CD 集成责任矩阵 / CI/CD integration RACI**
- 中：CI/CD 流水线由客户内部 DevOps 团队负责，但供应商需要支持哪些基础设施集成任务（Jenkins/Kubernetes 集成、环境变量配置等）？
- EN: CI/CD pipelines are managed by the customer's internal DevOps team — what infrastructure integration tasks (Jenkins/K8s integration, env config) must the vendor support?
- **阻塞级别**：中（边界不清 = 免费增项风险，须进 SOW 责任矩阵）

**Q9. 数据总量与跨境 / Data volume & cross-border**
- 中：数据迁移总量（含 DB、文件存储）是多少？大数据量迁移（>10TB）是否有计划？跨境数据传输限制是否影响迁移方案？
- EN: What is the total data migration volume (DB + file storage)? Is there a plan for large data volumes (>10TB)? Do cross-border data transfer restrictions affect the migration approach?
- **阻塞级别**：高（>10TB 触发专线/离线搬运档位；跨境触发 PIPL 评估）

**Q10. HyperCare 与回滚赔偿 / HyperCare & rollback penalty**
- 中：HyperCare 支持期限为每个 Wave 2–4 周，若 Wave 执行期间发生 P1/P2 故障导致回滚，HyperCare 是否重新计算？赔偿机制如何？
- EN: HyperCare is 2–4 weeks per wave. If a P1/P2 failure causes rollback, does HyperCare restart? What is the penalty mechanism?
- **阻塞级别**：**极高**（商务条款；未确认不得出 SOW 终版）

## 三、合规监管（11–14，中国区必问）

**Q11. 等保 MLPS 2.0 责任 / MLPS 2.0 responsibility**
- 中：MLPS 2.0 等级保护（2 级/3 级）的定级和备案是由供应商负责还是由客户自行完成？供应商是否需要协助准备测评材料？
- EN: Is MLPS 2.0 filing (Level 2/3) the vendor's responsibility or the customer's? Must the vendor assist in preparing assessment materials?
- **阻塞级别**：高（决定合规工作量归属与报价含否）

**Q12. PIPL 数据处理者身份 / PIPL data processor**
- 中：PIPL（个人信息保护法）对数据处理活动的要求中，供应商是否需要作为"数据处理者"签署相关协议？跨境数据传输评估是否已启动？
- EN: Under PIPL, must the vendor sign as a "data processor"? Has a cross-border data transfer assessment been initiated?
- **阻塞级别**：高（法务附件，须 `legal` 出具口径）

**Q13. ICP 备案是否在范围内 / ICP filing in scope?**
- 中：ICP 许可证申请是否在项目范围内？若客户需要在中国托管面向公众的服务，ICP Filing 的时间轴可能导致项目延期。
- EN: Is ICP license application within project scope? Hosting public-facing services in China requires ICP Filing, which may cause project delays.
- **阻塞级别**：中高（影响关键路径，须写入排期假设）

**Q14. 安全产品国产化替代 / Security product localization**
- 中：Zscaler 用于互联网出口流量检查 — Zscaler 是否已在中国区获批部署，是不是客户自行采购？还是需要替换为本地安全产品（如奇安信、深信服）？
- EN: Zscaler is required for internet egress inspection — is Zscaler approved for deployment in China? Or must it be replaced with a local security product?
- **阻塞级别**：高（安全设计 inputs；替换 = 额外选型与实施工作量）

## 四、其他（超量程项 / Out-of-range，第 15 条为**方法论**而非具体数值）

> **注意**：第 15 条原文含本例项目特定数值（26.8TB DB / 25TB NAS），属**示例**；换项目时应替换为该客户实际超量程项，或删除。

**Q15. 超量程数据项必须单列确认 / Out-of-range items must be confirmed separately**
- 中（本例原文）：C-Customer LTK 数据库：PROD 总量约 26.8TB，超出 High（3TB–12TB）区间，需与客户确认分阶段迁移方案 / CEVA CCLOG NAS：Appendix 1c 第 59 行显示 NAS = 25,000GB（25TB），远超任何 DB 迁移档位，是不是无需迁移。
- EN（本例原文）：C-Customer LTK DB PROD ≈ 26.8TB, exceeding the High (3TB–12TB) band — confirm a phased migration approach / CEVA CCLOG NAS = 25,000GB (25TB) per Appendix 1c row 59, far beyond any DB migration tier — confirm whether it is out of migration scope.
- **方法论（换项目时套用）**：凡单项数据量/规格**超出评估模型最大档位**的，一律**不套公式**，单列一行去客户处确认「分阶段迁移」还是「不迁移」；确认前该条目在估算中按 **0 计入并标注假设**，不得默认按最大档或线性外推。
- **阻塞级别**：高（超量程外推是报价失真主要来源）

## 五、访谈执行纪律 / Interview discipline

- **先问 5、10、11、12**（极高/高阻塞 + 商务/法务条款），这四个不落定，后面估算都是沙上建塔。
- 每题记录 **三列**：`客户原话 / 我方判读 / 待确认项`。判读与客户原话分列，**不得合并**（合并后无法溯源，且易被误认为客户已确认）。
- 客户答「你们看着办」→ 记「待确认 + 我方建议 X」，并**回写 SOW 假设章节**；不得当作已确认。
- **本清单不产生任何金额**。价格只在 `presales/pcs-quotation`；条款只在 `presales/pcs-sow` + `legal`；排期只在 `pm` / `pcs-wbs-*`。
