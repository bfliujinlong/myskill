# 认证备考包生产（Cert Exam Prep）

## When to Use
- 用户丢来认证名 / 考纲链接 / 考券邮件，要「备考计划」「模拟试题」「怎么准备这张证」
- 用户拿到 exam voucher / 优惠码问怎么用、何时考
- 已核实过考纲，要按域权重出题或排期
- 反触发：只问「这证难不难 / 值不值得考」走普通问答；简历投递类走 resume-optimizer；岗位面试题库（非认证考纲）走 career-ops

云/AI 认证备考包：核实官方考纲 → 算兑换券时限 → 按域权重分配天数与题数 → 出备考计划 docx + 模拟卷 docx。
触发词：备考、考证、模拟试题、exam voucher、认证考试、考纲，以及具体证书代号（AIF-C01 / AWS AI Engineer / AI-102 / HCIA 类）。

产出两份 docx（计划 + 模拟卷），黑灰版式，`MEDIA:` 发 Telegram。

## 流程

### 1. 先核实官方考试参数（不可凭记忆）

`web_search` 官方认证页 + exam guide PDF，拿齐：题数（计分项/不计分项分开）、时长、通过线（分制区间）、考试形式（考场/在线监考）、语言（有无简体中文）、门市价、考纲各域权重。

参数写进计划开头一行，标注「官方已核实」。记忆里的题数/时长常错一版（改版后旧数据仍在流传），**必须查到当版才写**。已核实参数与清单见 `references/exam-fact-check.md`。

### 2. 兑换券/优惠码：先算时限，再谈备考

考券邮件里的时限规则常有两层，混淆会导致券作废：

- **兑换窗口**（如「收到后 30 天内使用」）——「使用」的定义要读准：多数是**完成报名**而非考完试。
- **Use-By 日期**——考试日期上限。

所以计划第 0 天不是学习，是**报名订位**：位子订了备考才有锚点，且报名≠考试日期，改期通常有免费窗口（考前 24h+）。邮件里若强调「用同一邮箱」「关联 profile」，照抄进步骤——企业积分/合作伙伴权益常挂在这一步。

券码本身已进聊天记录时提醒用户别截图外发，但**不主动替用户改券码、不复述完整券码**。

### 3. 按域权重分配计划天数与模拟卷题数

权重是唯一客观的分配依据。同一份权重驱动两处：

| 用途 | 做法 |
|------|------|
| 计划天数 | 权重最高的域给最多天，且拆成「定位/全家桶」+「进阶/定制」两天 |
| 模拟卷题数 | 按权重比例分配到各域（如 20/24/28/14/14 → 10/12/14/7/7 = 50 题） |

计划里给每个域加一列**「你的底」**：结合用户真实背景（memory / cv）判断强弱，让弱域多占时间。用户是运维/迁移出身时，概念指标类和厂商产品边界类是弱项，实战经验对应的域是强项。

### 4. 免费资源优先（零费用硬约束）

只列官方免费项为主线：官方数字课/Learning Plan、免费 Practice Question Set、免费 Pretest、游戏化实验（Cloud Quest / Jam 类）。付费官方模考**单独标注价格 + 注明「非必须，本计划自带模拟卷」**，绝不默认用户会买。

### 5. 模拟卷规格

- 题型贴官方：单选/多选/排序/匹配/案例（看 exam guide 的 Question types 段）。基础级认证以「场景→选哪个服务/做法」为主，不考写代码、不考推导。
- **答案与解析集中放文末**，题面区不出现答案——否则没法限时自测。
- 每题带一行解析，解析要写出**为什么其他选项错**（干扰项套路才是训练价值）。
- 卷首声明「自编训练题，模拟出题思路与坑位，非官方原题」。不声明=用户可能当真题背。
- 给达标线：按通过分反推（如通过线 700/1000 → 建议 ≥70% 达标、≥80% 稳过）。

### 6. 计划里必含「考前一晚易错点备忘」

基础级认证的失分集中在**产品边界混淆**，不是知识盲区。把该认证的高频混淆对整理成 6–10 条一句话判据（「出现 X 字样选 A 服务，出现 Y 字样选 B 服务」），比再刷一套题有效。

### 7. 生成与 QA

docx 用 python-docx，黑灰无蓝，宋体正文/微软雅黑标题，表格 `Table Grid`。解释器路由与生成后文本层 QA（转义残留、私有区码点、选项字母断言）见 `tender-docx-assembly` 的「生成后 QA」节——**模拟卷这类批量结构化长文本必跑选项字母断言**。

交付后主动给下一步钩子：「刷题时把错题发我，我按域归因加练」。

## Pitfalls

- 别把「备考计划」写成通用学习建议清单。每一天要有**主题 + 资源 + 验收标准**三列，验收标准必须可判定（「默画 RAG 流程图」「12 服务×一句话用途默写」），否则用户执行不下去。
- 断档处理写进计划：某天没学就砍复盘日时长，**不顺延**——顺延会让考试日期撞上券的 Use-By。
- 在线监考（OnVU/Pearson VUE 类）的系统要求要提前一天检查并写进计划末日：关代理/VPN、关聊天软件、摄像头能拍四周、桌面清空。这些是当天翻车的主因，不是知识问题。
- 用户有「一人公司/自由职业」身份时，雇主型岗位的动机题（「你自己开公司为什么来打工」）是真实风险点，备考材料外要单独提示——但不编造动机，给叙事框架让用户自己认。
