# 青少年科创 / 雏鹰杯 / 青创赛 附件整理 — 真实素材提取与整理规则

## 适用场景
用户要求基于已有真实素材（查新报告/实验日志/研究报告初稿/课件）整理雏鹰杯/青创赛/少年科学院 附件 2-7，特别是附件 4（研究报告整理）/5（查新整理）/6（视频说明）/7（证明材料），输出 `docx`，黑灰配色，无蓝，去 AI 感，**不编人员/证书**。

## 提取规则（已验证 2026-09-25）
1. **确认文件**：`ls` + `file` 确认格式（RAR/DOCX/PDF）。RAR 无 `unrar`/`7z` 时直接告知，**勿猜测内容**。
2. **提取**：`zipfile.ZipFile(path)` 读 `word/document.xml` → `re.sub(r'<[^>]+>', '')` → `/tmp/<名>.txt`（防二次解析错位）。PDF 用 `pypdf.PdfReader`；多页长文只取前部关键字段（项目名/日期/实验环节/传感器/结论）。
3. **记录真实字段**：项目名（例：基于传感器技术的智能人体感应灯设计）、类别（创造发明/科学实验）、查新完成日（20260110）、实验环节日期序列（20250908 开题 → 20250915 背景 → 20250922 文献 → 20250929 实践 → 20251013 访谈 → 总结测试）、传感器型号（HC-SR501 / HC-SR04 / 光敏）、距离阈值（<50cm 动物 / 50-150cm 行人）、PWM 调光已实现（访谈张老师建议已采纳）。

## 铁律（不因“基于真实素材”而放松）
- **不编人员/证书**：附件 7 签名/盖章栏全部留空并标注“请申报者/指导教师/家长签字盖章”。教师真实访谈对象“张老师”仅可写“学校科技社团指导教师/访谈对象”，待申报者补签。**不可填“已签名”或“已盖章”。**
- **不虚构数据**：实验结论（误触发降低、距离识别准确）必须源自已提取实验日志（20250929 调通 + 20251013 PWM），不可凭“常识”补充新数据点。
- **不全篇粘贴**：整理版应提炼核心结论/数据/查新结论，保留来源引用（“整理依据：查新报告-刘依帆.docx（20260110）...”），避免全文粘贴导致格式混乱。
- **格式控制由脚本**：内容起草可 `delegate_task`（Azure `gpt-4o` `provider=azure-foundry`，已验证内容非空），但字体/配色/表格/去 AI 感必须 `execute_code` + `python-docx` 控制；不得让 AI 直接输出 docx（易出蓝色/机械格式/“AI”字眼）。

## 交付与渠道
- 输出：`docx`，`RGBColor(30,32,35)` 近黑文字，`微软雅黑` 标题/`宋体` 正文，`Table Grid`，无网格线硬边框。
- 压缩：`python3 scripts/compress_tender_docx.py <file.docx>`（q72，已验证 43.69MB→10.39MB，段落/表格零改动）。
- 发送：先确认文件大小；>20MB 先压缩；大文件优先飞书（100MB）或 dsh（CF 隧道）；Telegram 原生 20MB 限制直接拦截，不硬传。

## 已知坑（本轮验证）
- 用户只说“全部”仍缺：项目类别/已有素材/签名状态 → 必须反问确认，不能凭“全部”生成占位内容。
- `unrar`/`7z` 缺失 → RAR 提取失败，直接告知（本轮 `新.rar` 14.2MB 未解压）。
- `delegate_task` 起草内容可用（Azure gpt-4o 已验证内容非空），但格式配色仍须脚本控制。
- 真实访谈对象名称（“张老师”）只有在原文中出现时可引用，输出时仅可写“指导教师/访谈对象”，不可直接署名。
