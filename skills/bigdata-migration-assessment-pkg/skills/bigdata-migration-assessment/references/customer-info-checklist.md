# 待客户确认清单模板

每一项必须写明 **"缺了它会导致什么偏差"**，否则客户不会有动力提供。

分级：
- **P0** — 缺失会导致结论方向性错误，必须在报价前拿到
- **P1** — 缺失会导致 ±30% 以上偏差
- **P2** — 影响精度，可在实施前补齐

---

## P0 — 报价前必须拿到

| # | 需要的信息 | 缺失后果 |
|---|---|---|
| 1 | 源码仓库访问权限（或明确不开放） | 直接决定文档系数 1.0 还是 1.5，影响模型1 全量 ±50% |
| 2 | 现有架构文档 / 数据流图 | 同上；且无法验证模块边界与耦合度打分 |
| 3 | 完整作业清单：ETL 条数、SQL 条数、UDF 数、实时作业数，按引擎分类 | 模型3 全部无法测算 |
| 4 | 元数据规模：表数、分区数、库数，按元数据服务分类 | 元数据迁移与方言重写人天无法测算 |
| 5 | 各存储桶/文件系统的**实际容量**与增量速率 | 决定搬迁日历工期；PB 级项目工期风险大于人力风险 |
| 6 | 专线/带宽方案：带宽、是否已到位、可用传输窗口 | 决定带宽系数与日历工期，偏差可达数百天 |
| 7 | 迁移范围清单：哪些平台在范围内、哪些明确排除 | 范围漏项是报价差异的头号根因 |
| 8 | 责任矩阵逐项确认：代码改造、单元测试、版本发布、割接方案分别由谁做 | 责任错位会让我方多背数百人天 |
| 9 | 是否允许保留源端云服务的兼容层 | 决定是彻底重构还是兼容适配 |
| 10 | 我方标准服务目录（内部）确认版本 | 模型2/3 分界的唯一依据 |

## P1 — 影响 ±30% 以上

| # | 需要的信息 | 缺失后果 |
|---|---|---|
| 11 | 数仓表清单与表结构复杂度（宽表比例、存储过程数量） | 方言重写人天偏差大 |
| 12 | SQL 方言使用情况：是否大量使用引擎私有函数 | 决定重写是替换还是重构 |
| 13 | 数据一致性验收标准：抽样率、比对口径、谁出具报告 | 校验人天可差 3 倍 |
| 14 | 双跑并行要求：并行时长、并行期双端成本谁承担 | 双跑是隐性大项 |
| 15 | 割接窗口：可停机时长、是否允许分批割接 | 决定割接方案复杂度与加班系数 |
| 16 | 测试环境与开发环境是否由客户提供 | 环境搭建人天归属 |
| 17 | 合规要求：等保级别、数据是否可出域、审计链路要求 | 决定合规系数 1.0 还是 1.3 |
| 18 | GPU / 弹性伸缩类工作负载的实际使用模式 | 无等价托管服务，需定制方案 |
| 19 | 上下游系统清单（谁在消费这些数据） | 决定耦合度打分与回归测试范围 |
| 20 | 项目工期要求与里程碑 | 决定并行度与 PM 投入系数 |

## P2 — 影响精度

| # | 需要的信息 | 缺失后果 |
|---|---|---|
| 21 | 历史数据是否全量迁移，还是可按时间窗裁剪 | 可能大幅降低搬迁量 |
| 22 | 冷数据归档策略 | 同上 |
| 23 | 现有监控告警规则清单 | 影响日志/监控重建人天 |
| 24 | 权限模型现状（角色数、策略数） | 影响 IAM→CAM 人天 |
| 25 | 客户侧可投入的配合人力 | 影响我方值守与沟通成本 |

## 降本杠杆（必须一并给出）

每次评估都要把"客户做什么可以省钱"量化出来：

| 杠杆 | 动作 | 节省测算 |
|---|---|---|
| 文档系数 | 开放源码仓库 + 提供架构文档 | 模型1 × (1.5→1.0)，即节省 `模型1中值 ÷ 1.5 × 0.5` 人天 |
| 带宽系数 | 提供专线并保证带宽 ≥ 指定值 | 模型2 × (1.2→1.0)，并大幅压缩日历工期 |
| 范围裁剪 | 历史冷数据按时间窗裁剪 / 归档不迁 | 按裁掉的 GB 量重算模型2 |
| 自动化 | 同构部分允许用自动化工具 | 该部分 × 0.8 |
| 责任划分 | 集成测试/压测/割接执行由客户承担 | 按对应阶段权重扣减 |

写法示例：
> 客户开放源码 + 架构文档，文档系数由 ×1.5 降至 ×1.0，模型1 由 703.5 人天降至 469.0 人天，**节省 234.5 人天 ≈ 10.7 人月 ≈ ¥58 万（成本价）**。
