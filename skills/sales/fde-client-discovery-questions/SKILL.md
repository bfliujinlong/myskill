# FDE 客户首次拜访 · Discovery 提问准备

## When to Use
- 用户要去拜访/初见客户（售前 discovery / 首次需求会议），让你"准备一些问题"
- 用户说"见客户前帮我问问什么""客户发现清单""拜访问题"
- 任何需要在客户现场把模糊愿望变成可评估工作流的场景

## 核心来源
文章《FDE第一次见客户，到底应该问哪20个问题？》（FDE中国社区）：
FDE 第一次见客户的任务不是把方案讲完整，而是**判断一个模糊愿望背后有没有值得解决的真实工作流**。
好的发现必须从业务结果一直问到未来如何运行。

## 五组 20 问框架（不要机械按编号朗读，顺着回答追问）

### 第一组：结果（这个问题值不值得解决）
1. 这条流程最终要产生什么**业务结果**？（要求用结果而非功能回答）
2. 这个问题现在造成了什么**损失或错失**？（人工时间/等待/返工/投诉/收入泄漏/风险）
3. 这项工作**每天/每周发生多少次**？（频率决定价值规模与样本量）
4. 如果三个月后成功，**哪三个指标**会变化？（业务/质量/采用，至少三类）

→ 第一组结束应能写出一句问题陈述：谁+什么场景+什么摩擦+什么影响+希望哪项可测结果改善。

### 第二组：真实流程与例外
5. 什么事件**启动**这项工作，什么状态才算**真正完成**？（触发与结束定义边界）
6. 能不能**现场带我走一遍**最近一个真实案例？（看复制粘贴/私人表格/群确认/经验判断）
7. 正常路径外，**最常见的五种例外**是什么？（字段缺失/政策冲突/身份不明/超时/超限）
8. 哪一步**最慢、最易返工、最依赖个人经验**？（区分信息搬运/规则判断/关系协商/权责决定）

### 第三组：数据、知识与系统
9. 完成一次任务需要哪些信息，**分别在哪里**？（结构化字段/文档/邮件/对话/外部数据）
10. 哪个来源是**权威版本**，谁负责更新？（无 Owner 的知识库会快速失真）
11. 当前涉及哪些系统，**能读什么、写什么**？（CRM/ERP/工单/邮件/数仓；细化为只读/草稿/更新/发送/不可逆）
12. 能否提供一批**脱敏历史样本和对应正确结果**？（无样本无法建基线/评估集）

### 第四组：风险、权限、人工边界
13. 一次错误**最坏后果**是什么？（错误答案/错误写入/错误付款/错误拒绝，严重性可逆性不同）
14. 哪些数据**绝对不能访问/传出/长期保留**？（落实到字段/用户/区域/目的/保留期，由安全隐私法务确认）
15. 哪些动作**必须由人批准**，谁有决定权？（区分 AI 可完成/可准备供审核/必须由人担责）
16. 遇到缺失/冲突/低置信/越界时，**交给谁**？（升级是工作流一部分：停止条件/接收人/携带上下文/时限）

### 第五组：采用、Owner、商业决策
17. 谁是**业务 Owner**，谁能决定范围和验收？（发起需求 ≠ 对结果负责）
18. 谁会**每天使用或受影响**，他们现在在哪工作？（入口改变/重复登录/手工搬运的采用成本要计入）
19. 上线后谁负责**支持/监控/知识更新/事故处理**？（无持续 Owner 的 Agent 会失效）
20. 下一步**做什么，谁在什么时间提供什么证据**？（首会不必出最终报价，但必须有下一步+责任人+日期）

## 回答性质区分（会议记录要标注证据等级）
- **事实**：可回系统核验（"上月4280张工单，均解16h"）
- **判断**：一线经验，需跟岗/抽样验证（"查政策最费时"）
- **愿望**：目标，不能直接当基线（"效率翻倍"）
记录时标：已有系统数据 / 可现场提供样本 / 需 Owner 确认 / 暂为假设。

## 会议时间分配（60–90min）
前15min 目标背景 → 中40min 沿真实案例走流程 → 后20min 系统/风险/责任 → 末10min 复述已知未知+下一步。
国内企业特别留意**名义流程 vs 实际流程**差异（审批在系统、优先级在微信群；数据归某部、权限在集团IT）。

## 五件事判断（背后评估）
1. 问题是否真实且值得 2. 工作流能否被描述缩小 3. 数据系统能否支撑 4. 错误是否可控责任是否清 5. 组织能否采用并持续运营
→ 五项清楚进 PoC；价值清但流程乱先做标准化；数据缺先做样本审计；风险无相关方则把风险工作会当下一步。

## 会后交付五样（不要只发纪要）
1. 一句话问题陈述+预期结果 2. 当前流程/关键例外/痛点地图 3. 数据系统权限Owner清单 4. 初步AI/人工边界+主要风险 5. 下一步验证计划+责任人+时间
**未知项单独列**，区分：客户待提供 / FDE待验证 / 需安全或法务决策。

## 最不该做的三件事
1. 问题没清就展示所有产品能力（客户被功能带跑，真实流程被藏）
2. 只和高层谈愿景（高层定方向、一线掌例外、系统Owner知依赖、风险团队定边界，缺一方不完整）
3. 承诺未经数据流程验证的 ROI（可提假设和测量法，不可把估算说成结果）

## 本 skill 的使用方式（结合用户画像）
用户是上海安畅（MSP）的单兵 FDE，做云迁移/售前。触发"准备拜访客户问题"时：
1. 套用上面五组框架
2. **叠加用户当前项目背景**：如医药罕见病(病人数据/人类遗传资源合规)、云迁移(数据迁移/双跑/割接)、报价水位等真实素材
3. 输出：定制版拜访问题清单（按行业/项目裁剪，非机械20问全列）+ 会后交付模板（可直接当纪要骨架）
4. 若已知客户行业，优先强化对应组（如医疗→第四组风险合规权重拉满；云迁移→第三组系统权限+第五组 Owner）

## 输出物建议
- 拜访前：一页「定制问题清单」（按优先级排序，标注必问/选问）
- 拜访后：一份「会后交付五样」骨架，让用户直接填
