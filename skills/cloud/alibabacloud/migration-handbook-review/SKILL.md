# 迁移数据手册 Review

审阅客户/团队编写的迁移数据手册，找出问题：信息不一致、关键数据缺失、风险未识别、合规未提及、不可执行条款等。

## 输入

-  客户/团队编写的迁移手册（Word / PDF / Markdown / Confluence 页面）
-  适用的目标引擎与方案
-  历史 Review 报告（如有）

## 工作流

### 第 1 步 手册结构解析

按章节拆解，识别 7 类内容：

| 章节类型 | 应含内容 |
| --- | --- |
| 背景与目标 | 业务背景、迁移目标、验收指标 |
| 源端清单 | 系统清单、数据量、依赖关系 |
| 目标方案 | 架构图、组件清单、规格 |
| 实施路径 | 阶段划分、里程碑、回滚预案 |
| 风险 | 风险清单、概率、影响、应对 |
| 团队与责任 | RACI、沟通机制 |
| 验收标准 | 测试用例、性能指标 |

### 第 2 步 问题识别

按 6 类检查项打分：

| 检查项 | 关注 |
| --- | --- |
| **完整性** | 是否覆盖所有源端系统、是否包含边界场景 |
| **一致性** | 数据量、工期、人天是否前后一致 |
| **准确性** | 数字与口径、组件版本与配额 |
| **可行性** | 回滚方案、应急预案、人员可达性 |
| **合规性** | 数据驻留、加密、审计、GDPR/网络安全法 |
| **风险性** | 风险登记册、概率与影响评估、应对措施 |

### 第 3 步 输出 Review 报告

```
- 总评分：0–100
- 维度评分：完整性/一致性/准确性/可行性/合规性/风险性 各 0–100

- 问题清单（按严重性）：
  🔴 阻塞（必须解决才能开始迁移）
  ⚠️ 重要（影响方案质量）
  📝 建议（改进项）

- 每个问题：章节、原文摘录、问题描述、修改建议
```

### 第 4 步 改进建议模板

每个问题给一段可直接 copy 的改写建议：

```
原章节：5.2 实施路径
原文：「预计 4 周完成迁移」
问题：未拆分阶段、未标明依赖关系、未给里程碑

建议：
「实施路径分 3 个阶段：
  阶段 1（第 1-2 周）：网络与账号规划、应用适配改造
  阶段 2（第 3-4 周）：数据迁移、应用切换
  阶段 3（第 5 周）：稳定性观察与收尾
  
  里程碑：
  M1：网络打通、应用层 50% 适配完成
  M2：数据全量迁移完成、首批业务切流
  M3：全量切流完成、原环境保留 7 天」
```

## 输出交付物

| 文件 | 格式 |
| --- | --- |
| Review 总报告 | Markdown |
| 问题清单 | Excel（含严重性、章节、原文、建议） |
| 评分雷达图 | Mermaid / 图表 |
| 改写建议对照 | Markdown |

## 边界

- **不做**：替代业务专家决策（技术评审是辅助）。
- **依赖**：手册版本明确、未与其他评审交叉进行。
- **覆盖深度**：默认每章节抽 5–10 个关键点细审，全文逐字审阅需客户额外说明。
