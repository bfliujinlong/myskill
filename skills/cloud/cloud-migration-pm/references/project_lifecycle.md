# 项目全生命周期阶段分解

本文档详细描述云迁移项目从启动到复盘的 7 个阶段（00-06），包含每阶段的目标、具体任务、交付物清单、参与角色和阶段检查清单。

---

## 阶段 00：项目合同

**目标**：完成 SOW 签署，明确项目范围、交付物、工期与商务条款。

### 任务
1. 获取对应业务线的标准 SOW 模板（路径：`01服务流程/04其他/02产品SOW/0{N}-{前缀}-SOW/`）
2. 根据客户需求定制 SOW 内容（范围、交付物清单、工期、人员投入）
3. 内部评审 SOW（技术可行性、资源 availability）
4. 与客户确认并签署 SOW

### 交付物
- 定制化 SOW（`{客户}{业务线}服务说明书.docx`）
- 投入预估表（`.xlsx`，人员/工期/成本预估）

### 检查清单
- [ ] SOW 范围与客户需求一致
- [ ] 交付物清单明确且可验收
- [ ] 工期与资源配置合理
- [ ] 商务条款已确认

---

## 阶段 01：项目管理（启动）

**目标**：召开 KO 启动会，建立项目计划与 WBS，团队就位。

### 任务
1. 编写项目启动 PPT（KO 材料）
2. 拆解 WBS（工作分解结构），分配任务到人
3. 准备入场人员简历
4. 召开 KO 启动会（内部 + 客户）
5. 输出启动会会议纪要
6. 建立周报机制与会议节奏

### 交付物
| 交付物 | 格式 | 命名规范 |
|--------|------|----------|
| 项目启动 PPT | .pptx | `{客户} {业务线}项目启动V{YYYYMMDD}.pptx` |
| WBS 管理表 | .xlsx | `{客户}-{业务线}项目WBS管理_{YYYYMM}.xlsx` |
| 入场人员简历 | .docx | `{客户}入场人员简介.docx` |
| 启动会纪要 | .docx | `会议纪要{客户}项目 {YYYYMMDD}.docx` |
| 交付计划 | .xlsx | `{客户}项目-交付计划V{N}.xlsx` |

### KO 启动会内容要点
- 项目背景与目标
- 项目范围（含不包含的内容）
- 里程碑计划与关键节点
- 团队分工与职责
- 沟通机制（周会节奏、汇报路径）
- 风险与假设

### 检查清单
- [ ] KO PPT 已评审
- [ ] WBS 已拆解到可执行粒度（每个任务 ≤5 人天）
- [ ] 人员已确认就位
- [ ] 启动会已召开且纪要已发出
- [ ] 周报/会议节奏已建立

---

## 阶段 02：项目调研

**目标**：全面调研客户现有 IT 环境，输出调研报告，为方案设计提供输入。

### 任务
1. 发送并回收调研表（按业务线使用专用调研表）
2. 安排技术访谈（网络/安全/应用/数据各领域）
3. 收集现有环境资源清单
4. 分析调研结果，识别差距与风险
5. 输出调研报告 / 现状分析报告

### 交付物（按业务线）
| 业务线 | 调研表 | 调研报告 |
|--------|--------|----------|
| LZ | `【阿里云】Landing Zone 调研表.xlsx` | LZ-D-01 云上 IT 治理现状调研报告、LZ-D-02 合规差距分析报告 |
| WA | Well-Architected 审查问卷 | WA 现状评估报告 |
| BD | 数据梳理表、节点统计表 | 数据平台现状分析报告 |
| QY | IDC 迁云业务调研表、上云评估表 | IT 系统现状调研报告、迁移评估报告 |

### 调研要点
- **LZ**：账号体系、网络拓扑、安全策略、合规要求、现有标签体系
- **WA**：架构现状、成本分布、资源利用率、标签规范、运维流程
- **BD**：数据量、数据源、ETL 调度、SLA 要求、数据质量基线
- **QY**：业务系统清单、系统依赖、迁移窗口、割接约束、DR 要求

### 检查清单
- [ ] 调研表回收率 >90%
- [ ] 技术访谈覆盖所有关键领域
- [ ] 资源清单已收集完整
- [ ] 调研报告已输出并内部评审
- [ ] 差距与风险已识别

## 阶段 03：项目方案 / 方案设计

**目标**：完成 HLD 架构设计与 LLD 实施方案，通过评审。

### 任务
1. 编写 HLD（High Level Design）架构设计文档
2. 组织 HLD 评审会（内部 + 客户）
3. 根据评审意见修改 HLD
4. HLD 定稿后编写 LLD（Low Level Design）实施方案
5. 组织 LLD 评审会
6. 根据评审意见修改 LLD 至定稿

### 交付物
| 交付物 | 格式 | 命名规范 |
|--------|------|----------|
| HLD 架构设计 | .pptx | `{客户} {业务线} HLD-V{YYYYMMDD}.pptx` |
| LLD 实施方案 | .docx | `{客户} {业务线} LLD - V{YYYYMMDD}.docx` |
| 会议纪要 | .docx | `会议纪要{客户}项目 {YYYYMMDD}.docx` |

### HLD 内容要点
- 整体架构图（含组件、数据流、网络拓扑）
- 账号/资源组织架构
- 网络设计（VPC、TGW、专线、VPN）
- 安全架构（IAM、安全组、WAF、审计）
- 高可用与灾备设计
- 技术选型说明

### LLD 内容要点
- 详细实施方案（分步骤）
- IaC 代码结构与模块划分
- IP 地址规划表
- IAM 权限矩阵
- 标签策略 / SCP 策略设计
- 配置参数清单
- 实施前置条件与依赖

### 检查清单
- [ ] HLD 已编写并通过评审
- [ ] HLD 评审意见已闭环
- [ ] LLD 已编写并通过评审
- [ ] LLD 评审意见已闭环
- [ ] 方案与调研结果一致

---

## 阶段 04：项目交付 / 实施过程

**目标**：按 LLD 方案执行实施，完成部署、迁移、测试。

### 任务
1. 搭建实施环境（开发/测试/生产）
2. 编写与调试 IaC 代码（Terraform）
3. 分阶段部署（先基础架构，再安全策略，再业务适配）
4. 执行迁移操作（BD：数据搬栈；QY：业务割接）
5. 网络连通性测试
6. 安全合规检查
7. 日志链路验证
8. 持续输出周报与会议纪要

### 交付物
| 业务线 | 交付物 |
|--------|--------|
| LZ | LZ-D-10 已部署环境说明、LZ-D-11 IaC 代码仓库 README、LZ-D-12 安全基线配置清单 |
| LZ | LZ-D-13 合规检查报告、LZ-D-14 日志链路验证报告、LZ-D-15 网络连通性测试报告 |
| BD | 双跑验证报告、数据校验报告、ETL 迁移清单 |
| QY | DNS 改造文档、DR 策略与详细设计、DR 演练记录、单系统切换方案、割接总结 |
| 通用 | 部署交付物文档、实施过程周报 |

### 实施关键控制点
- 每个部署步骤需有回滚预案
- 生产环境操作需有变更审批
- BD 双跑期间需每日数据一致性校验
- QY 割接需有回滚窗口与回滚步骤

### 检查清单
- [ ] IaC 代码已通过 Code Review
- [ ] 基础架构部署完成并测试通过
- [ ] 安全策略已部署并验证
- [ ] 网络连通性测试通过
- [ ] 合规检查通过
- [ ] 日志链路验证通过
- [ ] 迁移/割接完成（BD/QY）

---

## 阶段 05：项目验收

**目标**：完成 UAT 测试与验收，获取客户验收签字。

### 任务
1. 编写 UAT 测试用例清单
2. 与客户共同执行 UAT 测试
3. 修复测试发现的问题
4. 汇总测试结果，输出验收报告
5. 客户签字确认验收
6. 输出项目总结报告

### 交付物
| 交付物 | 命名规范 |
|--------|----------|
| UAT 用例清单 | `LZ-D-16_UAT验收测试用例清单.docx` |
| 验收报告 | `LZ-D-17_验收报告.docx`（需客户签字） |
| 项目总结报告 | `LZ-D-18_项目总结报告.docx` |

### 验收标准
- 所有 UAT 测试用例通过（或遗留问题有明确处理计划）
- 交付物清单全部完成（对照 SOW 逐项确认）
- 客户满意度确认

### 检查清单
- [ ] UAT 用例已编写并经客户确认
- [ ] UAT 测试已执行完成
- [ ] 测试问题已修复或有处理计划
- [ ] 验收报告已输出
- [ ] 客户已签字验收
- [ ] 项目总结报告已输出

---

## 阶段 06：项目复盘

**目标**：总结经验教训，沉淀可复用资产。

### 任务
1. 组织内部复盘会
2. 总结做得好 / 做得差 / 改进项
3. 沉淀可复用的方案、模板、脚本
4. 归档项目文档
5. 更新知识库（如有）

### 交付物
- 项目复盘报告
- 经验教训清单
- 可复用资产归档（方案模板、IaC 模块、工具脚本）

### 复盘内容
- **做得好**：哪些做法值得保持和推广
- **做得差**：哪些环节出了问题，根因是什么
- **改进项**：下次项目如何改进，具体行动计划

### 检查清单
- [ ] 复盘会已召开
- [ ] 经验教训已记录
- [ ] 可复用资产已归档到 `01服务流程/`
- [ ] 项目文档已完整归档
