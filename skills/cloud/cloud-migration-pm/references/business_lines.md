## 一、LZ — Landing Zone 云上环境治理

### 业务定位
为客户构建标准化、安全、合规的云上多账号运行环境，作为后续上云的基础底座。

### 技术核心
1. **多账号组织架构**：Organizational Units 设计、Account 划分策略
2. **网络架构**：VPC 规划、Transit Gateway、VPN/专线、FortiGate HA
3. **安全合规**：IAM 权限矩阵、SCP 策略、标签策略、安全基线
4. **IaC 自动化**：Terraform 代码仓库、CI/CD 流水线

## 二、WA — Well-Architected 架构优化

### 业务定位
基于云厂商 Well-Architected Framework，对客户现有云上架构进行审查与优化，重点在成本优化（FinOps）与架构治理。

### 技术核心
1. **六大支柱审查**：卓越运营、安全、可靠性、性能效率、成本优化、可持续性
2. **FinOps 成本优化**：资源利用率分析、RI/SP 策略、闲置资源清理
3. **标签治理**：标签策略设计、资源分账、成本归因
4. **架构优化建议**：高可用改进、性能调优、安全加固

### 项目阶段（7 阶段制）
```
0 项目管理 → 1 项目启动 → 2 项目调研 → 3 方案设计
                                              ↓
6 项目复盘 ← 5 项目交付 ← 4 实施过程
```

### 典型交付物
| 交付物 | 说明 |
|--------|------|
| WA 审查报告 | 六大支柱评估结果与改进建议 |
| FinOps 成本优化方案 | 成本分析、优化建议、预期节省 |
| 标签治理方案 | 标签策略、分账规则、实施步骤 |
| 架构优化 HLD/LLD | 优化架构设计与实施方案 |
| 实施交付物 | 标签改造、成本优化执行结果 |
| 验收报告 | 优化效果验证 |

### SOW 模板路径

### 关键里程碑
1. 审查完成 → WA 审查报告交付
2. 优化方案确认 → HLD/LLD 评审通过
3. 优化实施完成 → 成本节省/标签覆盖率达标
4. 验收通过 → 效果验证报告

## 三、BD — 大数据迁移

### 业务定位
为客户完成大数据平台的跨云/上云迁移，包含数据搬栈、ETL 迁移、调度适配、数据校验全流程。

### 技术核心
1. **数据平台评估**：现有技术栈（Hadoop/Spark/Flink/数仓）、数据量、SLA
2. **搬栈方案**：离线迁移（全量+增量）、在线迁移（CDC 实时同步）
3. **ETL 迁移**：调度系统迁移（如 Airflow/DolphinScheduler）、脚本适配
4. **双跑验证**：新旧平台并行运行，数据一致性校验

### 项目阶段
```
00 工具 → 01 项目管理 → 02 项目调研 → 03 方案设计 → 04 项目交付
```

### 调研阶段重点
- 数据梳理（表/库/分区数量、存储量）
- 节点统计（计算节点、任务节点分布）
- 调度任务依赖分析
- 数据质量基线

### 典型交付物
| 交付物 | 说明 |
|--------|------|
| 数据梳理报告 | 表/库/分区/存储量统计 |
| 大数据架构 & 迁移方案设计 | HLD，含技术选型与迁移策略 |
| 双跑验证报告 | 新旧平台数据一致性校验结果 |
| ETL 迁移清单 | 迁移任务清单与适配记录 |
| UAT 用例清单 | BD-D-20 |

### SOW 模板路径
`01服务流程/04其他/02产品SOW/03BD-SOW/02/MSP_BigData_SOW_CN_V1.0.docx`

### 关键里程碑
1. 数据梳理完成 → 调研报告交付
2. 迁移方案确认 → 架构方案评审通过
3. 双跑启动 → 新旧平台并行
4. 数据校验通过 → 一致性确认
5. 割接完成 → 正式切换

## 四、QY — 迁云迁移

### 业务定位
将客户 IDC/其他云上的业务系统迁移至目标云平台，包含评估、规划、迁移、割接、灾备全流程。

### 技术核心
1. **迁移评估**：业务系统调研、迁移优先级排序、依赖分析
2. **迁移策略**：Rehost（平移）/ Replatform（改造）/ Repurchase（替换）选型
3. **割接方案**：DNS 切换、流量调度、灰度发布、回滚预案
4. **DR 灾备**：DR 策略设计、DR 演练、灾备体系搭建

### 典型交付序列（以华贵人寿为参考）
```
deliverable_01: 项目计划
deliverable_02: 实施方案
deliverable_03: 调研报告
deliverable_04: DNS 改造
deliverable_05: DR 策略
deliverable_06: DR 详细设计
deliverable_07: DR 计划
deliverable_08: DR 演练
deliverable_09: IDC 瘫痪指引
deliverable_10: 单系统切换
deliverable_11: 演练总结
deliverable_12: 培训材料
```

### 关键里程碑
1. 迁移评估完成 → 评估报告、迁移优先级
2. 迁移方案确认 → 实施方案评审通过
3. DR 体系搭建 → DR 策略 + DR 演练完成
4. 割接完成 → DNS 切换、系统切换成功
5. 验收通过 → 验收报告 + 培训交付

## 跨业务线通用规范

### IaC 业务线
- 前缀：IAC / AILZ
- 适用场景：Terraform 代码交付（可独立或随 LZ 项目交付）
- 代码仓库规范：模块化设计，含 README

### 交付物编号体系
| 业务线 | 编号格式 | 示例 |
|--------|----------|------|
| LZ | LZ-D-{NN} | LZ-D-04_HLD_架构设计文档.docx |
| BD | BD-D-{NN} | BD-D-20_UAT用例清单.docx |
| QY | deliverable_{NN} | deliverable_01_项目计划.docx |
| WA | WA-D-{NN} | WA-D-01_WA审查报告.docx |

- QY/BD 项目（国内客户为主）：中文为主
- WA 项目：视客户需求
