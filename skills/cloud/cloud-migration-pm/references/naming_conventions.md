# 命名规范与目录结构

本文档规范云迁移项目中项目命名、目录结构、文档版本和交付物编号的规则。

---

## 一、项目命名

### 项目目录命名
```
{业务线前缀}-{客户名}
```

| 前缀 | 业务线 | 示例 |
|------|--------|------|
| LZ | Landing Zone | `LZ-奥芯明`、`LZ-GSK`、`LZ-Lilly礼来` |
| WA | Well-Architected | `WA-EPSON`、`WA-移远通信`、`WA-联电` |
| BD | Big Data 大数据 | `BD-汤臣倍健项目`、`BD-牧原`、`BD-广州诗悦` |
| QY | 迁云迁移 | `QY-康师傅`、`QY-美图秀秀`、`QY-华贵人寿` |
| IAC | Infrastructure as Code | `IAC-lilly`、`IAC-北京A客户` |
| AILZ | AI + Landing Zone | `AILZ-阿普塔` |

### 复合业务线
当项目跨多个业务线时，用 ` + ` 或组合前缀：
- `LZ + IAC Tapestry - 阿里云`
- `LZ金鹰国际 REG`（LZ + Region）

## 二、项目目录结构

### 标准阶段化目录（编号前缀）
每个项目目录下按编号阶段创建子目录：

```
{前缀}-{客户名}/
├── 00项目合同/          SOW、合同、投入预估
├── 01项目管理/          KO、WBS、人员简历、周会
│   ├── 00项目计划模板/
│   ├── 01人员简历/
│   ├── 02人员招聘/
│   └── 03周会/
├── 02项目调研/          调研表、资源清单、调研报告
│   └── 01数据梳理/      (BD 项目)
├── 03项目方案/          (或 03方案设计/)
│   ├── 交付/
│   └── 会议纪要*.docx
├── 04项目交付/          (或 04实施过程/)
│   ├── 01交付邮件/
│   ├── 02OA迁移/
│   └── 01双跑/          (BD 项目)
├── 05项目验收/          UAT、验收报告
├── 06项目复盘/          复盘报告
└── {客户}{业务线}服务说明书.docx
```

### 阶段编号对照
| 编号 | 阶段 | 必选 |
|------|------|------|
| 00 | 项目合同 | 是 |
| 01 | 项目管理 | 是 |
| 02 | 项目调研 | 是 |
| 03 | 项目方案/方案设计 | 是 |
| 04 | 项目交付/实施过程 | 是 |
| 05 | 项目验收 | 推荐 |
| 06 | 项目复盘 | 推荐 |

### 业务线目录差异
- **LZ**：`03项目方案` + `04项目交付`
- **BD**：`03方案设计`（含数据梳理子目录）
- **WA**：`0项目管理` ~ `6项目复盘`（不带"项目"前缀，编号 0-6）
- **QY**：同 LZ 标准结构

## 三、文档版本命名

### 日期版本（主用）
```
{文件名}-V{YYYYMMDD}.{扩展名}
```
- 示例：`奥芯明 Landing Zone HLD-V20260209.pptx`
- 示例：`奥芯明 Landing Zone LLD - V20260305.docx`

### 语义版本（辅用）
```
{文件名}_V{Major}.{Minor}.{扩展名}
```
- 示例：`MSP_LandingZone_SOW_CN_V1.0.docx`
- 示例：`汤臣倍健-大数据迁移工作计划_V1.1.xlsx`

### 状态标记
| 标记 | 含义 | 示例 |
|------|------|------|
| `更新中` | 文档编写中，未定稿 | `LLD - V20260305 - 更新中.docx` |
| `V1` | 修改后的第一版 | `会议纪要奥芯明项目 20260226V1.docx` |
| `V2` | 修改后的第二版 | `项目启动20260130V2.pptx` |
| `初版` | 初稿 | `项目计划初版.pptx` |
| `定稿` | 最终版本 | 通常不加后缀，取最新 V 日期版 |

### 版本管理建议
- HLD/LLD 使用日期版本，每次修改更新日期
- 会议纪要修改后在日期后加 V1、V2
- SOW/模板文件使用语义版本（V1.0, V1.1）
- 评审通过版本去掉"更新中"标记

## 四、交付物编号体系

### LZ 交付物编号
```
LZ-D-{NN}_{交付物名称}.docx
```
- 编号范围：LZ-D-01 ~ LZ-D-21
- 示例：`LZ-D-04_HLD_架构设计文档.docx`

### BD 交付物编号
```
BD-D-{NN}_{交付物名称}.docx
```
- 示例：`BD-D-20_UAT用例清单.docx`

### QY 交付物编号
```
deliverable_{NN}_{交付物名称}.docx
```
- 示例：`deliverable_01_项目计划.docx`
- 示例：`deliverable_05_DR策略.docx`

### WA 交付物编号
```
WA-D-{NN}_{交付物名称}.docx
```

## 五、会议纪要命名

### 标准格式
```
会议纪要{客户名}项目 {YYYYMMDD}.docx
```
- 示例：`会议纪要奥芯明项目 20260226.docx`
- 示例：`会议纪要奥芯明项目 20260312.docx`

### 修改版本
```
会议纪要{客户名}项目 {YYYYMMDD}V{N}.docx
```
- 示例：`会议纪要奥芯明项目 20260226V1.docx`

### 多格式存档
同时输出 .docx 和 .pdf：
- `会议纪要奥芯明项目 20260226.docx`
- `会议纪要奥芯明项目 20260226.pdf`

- HLD: `{Client} Landing Zone HLD-V{YYYYMMDD}.pptx`

## 八、代码文件规范

### IaC 代码（Terraform）
- 扩展名：`.tf` / `.hcl`
- 模块化设计，每个模块含 README
- 仓库命名：`{客户}-{业务线}-iac` 或 `iac-{客户}`

### 内部工具
- Python 脚本：`.py`（如 `create_lz_sow.py`、`create_wbs_tab.py`）
- Web 工具：React + TypeScript（如 `cloud_migration_assessment_tool`）
- 脚本放项目 `00工具/` 目录或独立工具仓库
