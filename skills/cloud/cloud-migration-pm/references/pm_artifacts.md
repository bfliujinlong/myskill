# 项目管理交付物规范与模板

本文档规范云迁移项目中各类项目管理交付物的格式、内容要点和编写指南。

---

## 一、WBS 管理表

### 文件规范
- **格式**：.xlsx
- **命名**：`{客户}-{业务线}项目WBS管理_{YYYYMM}.xlsx`
- **示例**：`奥芯明-阿里云LZ项目WBS管理_202601.xlsx`

### 内容结构
| 列 | 说明 |
|----|------|
| WBS 编号 | 层级编号（1 / 1.1 / 1.1.1） |
| 任务名称 | 简明任务描述 |
| 阶段 | 00-06 对应阶段 |
| 负责人 | 任务责任人 |
| 计划开始 | 日期 |
| 计划结束 | 日期 |
| 工期（人天） | 预估工作量 |
| 实际完成 | 日期/百分比 |
| 状态 | 未开始/进行中/已完成/阻塞 |
| 依赖 | 前置任务编号 |
| 交付物 | 关联交付物编号（如 LZ-D-04） |

### 编写要点
- 拆解到可执行粒度：每个叶子任务 ≤5 人天
- 标注任务依赖关系，识别关键路径
- 交付物列关联标准交付物编号，便于追溯
- 周度更新实际进度，偏差 >5% 需标红预警

## 二、项目启动 PPT（KO 材料）

### 文件规范
- **格式**：.pptx
- **命名**：`{客户} {业务线}项目启动V{YYYYMMDD}.pptx`
- **示例**：`奥芯明 LandingZone项目启动20260203.pptx`

### 内容结构
1. **封面**：项目名称、客户 logo、日期
2. **项目背景**：为什么做这个项目
3. **项目目标**：可量化的目标（如：构建 5 账号 LZ 体系，合规通过率 100%）
4. **项目范围**：包含 / 不包含的内容
5. **里程碑计划**：关键节点与交付时间
6. **WBS 概览**：主要工作包分解
7. **团队分工**：角色与职责矩阵
8. **沟通机制**：周会节奏、汇报路径、升级机制
9. **风险与假设**：已识别风险与前提条件
10. **下一步计划**：近期行动项

## 三、周报

### 文件规范
- **格式**：.docx
- **命名**：`{业务线}-{阶段}-周报-{YYYYMMDD}.docx`
- **示例**：`AI原生-大数据搬栈-迁移阶段-20260604-周报.docx`

### 内容结构
1. **本周进展**：完成的任务与交付物
2. **下周计划**：下周重点任务
3. **风险与问题**：当前风险项与处理措施
4. **需协调事项**：需要上级或客户支持的事项

### 编写要点
- 进展描述具体到交付物（如"完成 LZ-D-04 HLD 初稿"）
- 风险需标注等级（高/中/低）和责任人
- 每周一发出，覆盖上周工作

## 四、会议纪要

### 文件规范
- **格式**：.docx（同时输出 .pdf 存档）
- **命名**：`会议纪要{客户}项目 {YYYYMMDD}.docx`
- **版本**：修改后加 V1 后缀（如 `会议纪要奥芯明项目 20260226V1.docx`）
- **时效**：会议后 24h 内输出

### 内容结构
1. **会议信息**：日期、地点、参会人（内部 + 客户）
2. **会议议题**：讨论主题列表
3. **讨论内容**：各议题的讨论要点
4. **会议决议**：达成的共识（编号列出）
5. **待办事项**：任务、责任人、截止日期（表格形式）

### 待办事项表格
| 序号 | 待办事项 | 责任人 | 截止日期 | 状态 |
|------|----------|--------|----------|------|
| 1 | ... | ... | ... | 未开始/进行中/已完成 |

## 五、风险登记册

### 文件规范
- **格式**：.xlsx 或 .csv
- **命名**：`{客户}项目风险登记册_{YYYYMM}.xlsx`

### 内容结构
| 列 | 说明 |
|----|------|
| 风险编号 | R-001, R-002... |
| 风险描述 | 风险事件描述 |
| 风险类别 | 技术/进度/资源/客户/合规 |
| 概率 | 高/中/低 |
| 影响 | 高/中/低 |
| 风险等级 | = 概率 × 影响 |
| 触发条件 | 什么情况下风险会发生 |
| 应对策略 | 规避/转移/减轻/接受 |
| 应对措施 | 具体行动 |
| 责任人 | 风险责任人 |
| 状态 | 未关闭/已关闭 |
| 更新日期 | 最后更新时间 |

### 风险等级矩阵
| | 影响-高 | 影响-中 | 影响-低 |
|---|---|---|---|
| **概率-高** | 高 | 高 | 中 |
| **概率-中** | 高 | 中 | 低 |
| **概率-低** | 中 | 低 | 低 |

- **高风险**：需立即升级处理，制定应对计划
- **中风险**：需跟踪监控，制定预案
- **低风险**：记录观察

## 六、UAT 验收测试用例清单

### 文件规范
- **格式**：.docx
- **命名**：`{业务线}-D-{NN}_UAT验收测试用例清单.docx`（如 `LZ-D-16_UAT验收测试用例清单.docx`）

### 内容结构
| 列 | 说明 |
|----|------|
| 用例编号 | TC-001, TC-002... |
| 测试模块 | 网络/IAM/安全/合规/日志... |
| 测试场景 | 测试目标描述 |
| 前置条件 | 测试前置要求 |
| 测试步骤 | 操作步骤 |
| 预期结果 | 期望的测试结果 |
| 实际结果 | 实际测试结果 |
| 状态 | Pass/Fail/Blocked/N/A |
| 备注 | 问题说明 |

### 验收标准
- 所有用例状态为 Pass（或遗留问题有明确处理计划）
- Fail 用例需有修复计划与复测安排
- Blocked 用例需说明阻塞原因

## 七、验收报告

### 文件规范
- **格式**：.docx
- **命名**：`{业务线}-D-{NN}_验收报告.docx`（如 `LZ-D-17_验收报告.docx`）
- **要求**：需客户签字确认

### 内容结构
1. **项目概述**：项目名称、周期、范围
2. **交付物清单**：对照 SOW 逐项确认（表格）
3. **验收测试结果**：UAT 用例通过率统计
4. **遗留问题**：未关闭项与处理计划
5. **验收结论**：通过 / 有条件通过 / 不通过
6. **签字确认**：双方签字（日期、签名）

### 交付物确认表
| 序号 | 交付物编号 | 交付物名称 | 状态 | 备注 |
|------|-----------|-----------|------|------|
| 1 | LZ-D-01 | 云上 IT 治理现状调研报告 | 已交付 | |
| 2 | LZ-D-04 | HLD 架构设计文档 | 已交付 | |
| ... | ... | ... | ... | |

## 八、项目总结报告

### 文件规范
- **格式**：.docx
- **命名**：`{业务线}-D-{NN}_项目总结报告.docx`（如 `LZ-D-18_项目总结报告.docx`）

### 内容结构
1. **项目概述**：背景、目标、周期、团队
2. **交付成果**：实际交付内容与成果
3. **里程碑回顾**：计划 vs 实际对比
4. **工作量统计**：计划 vs 实际人天
5. **经验与教训**：做得好 / 改进项
6. **后续建议**：运维、优化建议

## 九、项目复盘报告

### 文件规范
- **格式**：.docx
- **位置**：项目目录 `06项目复盘/` 下

### 内容结构
1. **复盘背景**：项目基本情况
2. **做得好**：值得保持和推广的做法（3-5 条）
3. **做得差**：需要改进的环节（3-5 条，含根因分析）
4. **改进行动计划**：具体改进措施、责任人、时间节点
5. **可复用资产**：沉淀的方案模板、IaC 模块、工具脚本

### 复盘原则
- 对事不对人
- 聚焦改进而非追责
- 每个问题都要有改进行动项
- 可复用资产归档到 `01服务流程/` 对应目录
