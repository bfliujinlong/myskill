# 云迁移项目管理与技术管理

## 概述

本技能为云迁移、大数据、Landing Zone、Well-Architected 四类项目提供从启动到复盘的全流程管理指南。涵盖项目管理（计划、周报、会议、风险、验收）与技术管理（调研、方案设计 HLD/LLD、实施、交付）两条主线，遵循编号阶段化交付体系。

## 四大业务线

| 前缀 | 业务线 | 全称 | 核心目标 |
|------|--------|------|----------|
| **LZ** | Landing Zone | 云上环境治理 | 多账号体系、网络、安全、合规、IaC 治理基线 |
| **WA** | Well-Architected | 架构优化 | 六大支柱审查、FinOps 成本优化、分账治理 |
| **BD** | Big Data | 大数据迁移 | 数据平台搬栈、ETL 迁移、双跑验证、数据校验 |
| **QY** | 迁云 | 云迁移 | IDC 迁云、业务割接、DR 灾备、系统切换 |

详细业务线工作流与交付物清单见 `references/business_lines.md`。

## 项目全生命周期（7 阶段）

所有项目遵循编号阶段化目录结构，阶段间有明确的前后依赖关系：

```
00 项目合同    →  01 项目管理    →  02 项目调研
     ↓               ↓               ↓
 SOW 签署       KO 启动会        调研表/HLD 草案
                                        ↓
 06 项目复盘   ←  05 项目验收    ←  03 项目方案  ←  04 项目交付
     ↓               ↓               ↓               ↓
 经验沉淀      UAT/验收报告      LLD/实施       双跑/割接/部署
```

各阶段详细任务、交付物、检查清单见 `references/project_lifecycle.md`。

## 双线管理模型

### 项目管理线（PM Track）

贯穿全生命周期，核心交付物：

| 阶段 | PM 交付物 | 规范 |
|------|-----------|------|
| 01 启动 | 项目启动 PPT（KO）、WBS 管理表、人员简历 | 启动会需覆盖目标/范围/里程碑/分工 |
| 01-04 执行 | 周报（每周）、会议纪要（每次会议） | 周报含进展/风险/下周计划；纪要含决议/待办/责任人 |
| 01-04 执行 | 风险登记册、里程碑跟踪 | 风险分级（高/中/低），里程碑偏差 >5% 需预警 |
| 05 验收 | UAT 用例清单、验收报告 | 验收报告需客户签字确认 |
| 06 复盘 | 项目总结报告、经验教训 | 复盘覆盖做得好/做得差/改进项 |

PM 交付物格式与模板见 `references/pm_artifacts.md`。

### 技术管理线（Tech Track）

按阶段推进，核心交付物：

| 阶段 | 技术交付物 | 关键审查点 |
|------|-----------|-----------|
| 02 调研 | 调研表（LZ/WA/BD 专用）、资源清单、IT 现状报告 | 调研覆盖率需 >90% 业务系统 |
| 03 方案 | HLD 架构设计（PPT）、LLD 实施方案（DOCX） | HLD 需评审通过后才能出 LLD |
| 04 交付 | IaC 代码、部署交付物、测试报告、迁移文档 | LLD 评审通过后才能实施 |
| 05 验收 | 合规检查报告、网络连通性报告、日志验证报告 | 所有检查项需 Pass |

## 核心工作流

### 工作流 1：新项目启动

当接到新项目时，按以下步骤执行：

1. **确认业务线**：判断项目属于 LZ / WA / BD / QY，确定前缀
2. **创建项目目录**：在 `02项目/` 下按 `{前缀}-{客户名}` 命名（如 `LZ-奥芯明`）
3. **创建阶段子目录**：`00项目合同` → `01项目管理` → `02项目调研` → `03项目方案` → `04项目交付`（→ `05项目验收` → `06项目复盘`）
4. **获取 SOW 模板**：从 `01服务流程/04其他/02产品SOW/0{N}-{前缀}-SOW/` 获取对应业务线的标准 SOW
5. **编写启动 PPT**：覆盖项目背景、目标、范围、里程碑、WBS、团队分工
6. **建立 WBS 管理表**：拆解任务到可执行粒度，分配责任人，标注工期与依赖
7. **召开 KO 启动会**：内部+客户对齐，输出会议纪要

命名规范见 `references/naming_conventions.md`。

### 工作流 2：方案设计

方案设计是技术管理核心，分两步：

**第一步：HLD（High Level Design）**
- 格式：PPT（便于评审汇报）
- 内容：整体架构图、账号体系、网络拓扑、安全架构、高可用设计、技术选型
- 版本命名：`{客户} {业务线} HLD-V{YYYYMMDD}.pptx`（如 `奥芯明 Landing Zone HLD-V20260209.pptx`）
- 审查：HLD 评审通过后才能进入 LLD

**第二步：LLD（Low Level Design）**
- 格式：DOCX（便于详细描述）
- 内容：详细实施方案、IaC 代码结构、配置参数、IP 规划、IAM 矩阵、标签/SCP 策略
- 版本命名：`{客户} {业务线} LLD - V{YYYYMMDD}.docx`（开发中标注"更新中"）
- 审查：LLD 评审通过后才能进入实施交付

### 工作流 3：项目执行管控

项目执行期间持续产出：

1. **周报**：每周更新，含本周进展、风险问题、下周计划
2. **会议纪要**：每次客户会议后 24h 内输出，格式 `会议纪要{客户}项目 {YYYYMMDD}.docx`
3. **风险跟踪**：维护风险登记册，高风险需升级处理
4. **里程碑审查**：每个里程碑节点需对照 WBS 检查偏差

### 工作流 4：交付与验收

1. **交付物清单**：按业务线标准交付物编号体系输出（如 LZ-D-01 ~ LZ-D-21）
2. **UAT 测试**：编写 UAT 用例清单，与客户共同执行测试
3. **验收报告**：汇总测试结果，输出验收报告，需客户签字
4. **项目总结**：输出项目总结报告，含交付内容、成果、经验教训

### 工作流 5：项目复盘

1. **内部复盘**：团队回顾做得好/做得差/改进项
2. **经验沉淀**：将可复用的方案、模板、经验归档到 `01服务流程/`
3. **文档归档**：确保所有交付物完整归档到项目目录

## 技术管理关键要点

### LZ（Landing Zone）核心技术
- 多账号组织架构设计（Organizational Units + Accounts）
- 网络架构（VPC/Transit Gateway/VPN/专线）
- 安全合规（IAM 权限矩阵、SCP 策略、标签策略、安全基线）
- IaC 自动化（Terraform，代码仓库 README）

### WA（Well-Architected）核心技术
- 六大支柱审查（卓越运营、安全、可靠性、性能效率、成本优化、可持续性）
- FinOps 成本优化（资源利用率分析、RI/SP 策略、分账治理）
- 标签治理改造（标签策略设计、资源分账）

### BD（大数据迁移）核心技术
- 数据平台架构评估（现有技术栈、数据量、SLA）
- 搬栈方案设计（离线/在线迁移、数据校验策略）
- ETL 迁移与适配（调度系统迁移、脚本适配）
- 双跑验证（新旧平台并行，数据一致性校验）

### QY（迁云）核心技术
- IDC 迁云评估（业务系统调研、迁移优先级、依赖分析）
- 迁移方案设计（rehost/replatform/repurchase 选型）
- 割接方案（DNS 切换、流量调度、回滚预案）
- DR 灾备（DR 策略、DR 详细设计、DR 演练）

## 快速参考

**新建项目时**：确认业务线前缀 → 创建编号阶段目录 → 获取对应 SOW 模板 → 编写启动 PPT + WBS → 召开 KO

**写方案时**：先 HLD（PPT，评审用）→ 评审通过 → 再 LLD（DOCX，实施用）→ 评审通过 → 进入交付

**写周报/纪要时**：周报每周一更，纪要 24h 内输出，格式固定为 `会议纪要{客户}项目 {YYYYMMDD}.docx`

**验收时**：UAT 用例 → 测试执行 → 验收报告（客户签字）→ 项目总结 → 复盘归档
