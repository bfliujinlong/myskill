# 售前与报价规范

## 报价输出
- 单价基准 **$350/人天**，任何偏离必须在文档里说明理由。
- 结构顺序：项目背景 → 范围与假设 → 资源评估结论 → 工作分解（WBS）→ 人天测算表 → 商务条款 → 待确认清单。
- 人天测算表至少包含列：**角色 / 工作内容 / 人天 / 单价 / 小计**。
- **待确认清单必写**：RTO/RPO、停机窗口、数据增量、第三方 License、是否有等保/合规要求。

## 双语
- 对外文档一律中英双语，两个版本**分开成文件**（如 `报价_CN.docx` / `Quotation_EN.docx`）。
- 不是逐句直译：英文版按英文商务习惯重写，去掉中文版里的客套与铺垫。
- 术语统一：Landing Zone、Availability Zone、SOW、Migration Wave 不翻译。

## 去 AI 味（重要）
禁止出现：
- 空洞开场："在当今数字化转型的浪潮中""随着云计算的快速发展"
- 滥用的词：赋能、抓手、闭环、一站式、全方位、深度融合
- 机械连接词：每条都以"首先/其次/最后"开头，或每段都以"需要注意的是"结尾
- 无意义的形容词堆砌："高效稳定的云架构"

应该：
- 直接给结论和数字
- 用客户自己的系统名、真实资源量、真实业务峰值说话
- 风险部分诚实写明"这个量级下常见的问题是 X，我们的应对是 Y"

## 客户沟通
- 海外客户（如中东 Fintech 方向）：默认英文沟通，回复保留专业克制，不过度承诺。
- 讲方案时先讲**业务影响**再讲技术细节：迁移对业务停机多久、数据会不会丢、成本变多少。
- 客户问到未核实的数字，答"我核实后给你准确值"，不要当场估算后当结论说。

## 交付物格式
- 报价、方案、SOW：Word(.docx)
- 讲解材料：PPT，一页一个结论，不放大段文字
- 内部测算：Excel，公式可追溯
