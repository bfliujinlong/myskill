## 4. 服务范围与责任（RACI）

约定：**R**=负责执行 ｜ **C**=协助建议 ｜ **I**=知情人；甲方含其第三方合作伙伴。

| 活动 | 乙方 | 甲方 | 备注 |
|---|---|---|---|
| 0 准备阶段 环境授权与账号开通 | C | R | 云资源由甲方主导 |
| 1 现状调研 系统清单与依赖拓扑 | R | C | 以调研确认版为基线 |
| 2 方案设计 | R | C | 甲方确认方案 |
| 3 实施 | R | C | 甲方配合【停机窗口/审批】 |
| 4 验证后保障 结果分析与整改 | R | I | 整改由甲方落责 |

> **风险敞口控制写法**：整体云资源与业务架构梳理由甲方主导（C/R）；【核心服务】设计与执行由乙方主导（R/C）。

## 5. 各方责任

**5.1 甲方责任**
1. 提供【目标云】账号、资源访问授权与配额保障
2. 确认【对象】的目标（如 RTO/RPO）与【窗口】
3. 指定对接人，配合协调
4. 提供系统架构、依赖关系、历史记录等必要资料
5. 负责数据脱敏与合规审批
6. 对乙方出具的整改建议承担落责与实施
7. 及时确认各阶段交付物与验收节点
8. 承担第三方 License 与 SaaS 系统的责任
9. 保障期间业务侧配合

**5.2 乙方服务范围与责任**
- 输出【主服务】方案、计划与 SOP（含回滚）
- 执行【核心动作】与实测
- 出具报告与整改建议
- 知识转移与复盘

**5.3 乙方排除项**（走 PCR 增补）：应用代码改造、业务逻辑调整与测试；数据库表逻辑结构重新设计；清单外系统；硬件/机房搬迁；第三方 License 费用；业务层深度重构；数据治理/等保合规咨询；建模与报表；验收后日常运维；排除地域。

## 6. 服务流程与方式

**6.1 服务流程**（需求提出 → 内容与方案确认 → 实施 → 验收）

| 步骤 | 内容 | 完工标准 |
|---|---|---|
| 1 需求提出 | 甲方提出范围与目标 | 范围清单与目标确认 |
| 2 方案确认 | 乙方输出方案与 SOW | 方案经甲方书面/在线确认 |
| 3 实施 | 【核心动作】 | 每【对象】完成并记录 |
| 4 验收 | 报告交付与验收 | 验收报告经双方确认签署 |

**6.2 服务方式**：现场 / 远程 / 混合；人员更换提前 **72 小时**告知。

## 7. 服务完成标准与交付物

**7.1 验收标准**
1. 提交各阶段交付物
2. **不以人天签到或出勤为依据**（服务包模式）；人天模式则按人天明细验收
3. 以《【项目】系统范围清单（调研确认版）》+ 各阶段交付物 + **完成【对象】数量**为准
4. 每【对象】须：【动作】+ 数据一致性确认 + 指标实测通过 + 双方确认完成 + 无重大业务影响
5. 各模块**分别验收、互不依赖**
6. 阶段交付物经甲方书面/在线确认即视为该阶段验收通过

**7.2 阶段交付物表**

| 阶段 | 交付物 |
|---|---|
| 1 启动 | 启动会 PPT + 会议纪要 |
| 2 调研 | 调研报告 / 系统依赖关联表 / 原资源清单 |
| 3 方案设计 | 【服务】方案（含安全配置 checklist、全量任务检查清单） |
| 4 实施 | 操作 SOP（含回滚）/ 验证测试报告 / 技术问题日志 |
| 5 验证分析 | 指标实测对比报告 / 整改建议清单 |
| 6 保障 | 复盘与监控报告（后【N】日内） |
| 7 验收 | 验收报告（含总结 PPT）/ 项目验收文档 |
| 项目管理 | 周报、会议纪要、阶段性汇报 |

## 附录 E 安畅 MSP 交付口径（厂家中立）

**E.1 定位**
- 乙方为**厂家中立 MSP**：目标云按甲方选型执行
- 无厂家色时（多云/中立项目）默认使用本套（安畅红）模板

**E.2 SmartCare 服务体系口径**
- 交付阶段沿用 SmartCare：咨询评估 → 规划设计 → 迁移实施 → 托管运维 → 持续优化
- 人天仅作能力与工作量评估依据，**不作为结算/签到/出勤验收依据**（服务包模式）

**E.3 责任边界（MSP 通用）**
- 云厂商侧资源开通、配额、工单与账号实名由甲方主导，乙方协助
- 目标端平台整体架构设计责任方在责任矩阵中写明

**E.4 禁止事项（红线）**
- 不虚构人名、角色、证书、案例（废标风险）
- 不自行测算报价，商务章只引用 `mig-quotation` 产出
- 不在文档中虚构客户名，未授权时匿名 `xx customer`
