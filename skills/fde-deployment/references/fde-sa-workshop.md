# FDE + SA/TAM 协同售前共识（2026-08-22 workshop，安畅&咖墨 共创）

本文件沉淀 workshop 产出的"售前流程 + 弹药库 + 能力机制"三层结构，供 fde-deployment 编排层对齐使用。核心一句话：**SA/TAM 管"方案对不对"，FDE 管"在现场跑不跑得通"；把 SA 的 8 步每步加一条 FDE 可执行验证红线。**

## 1. 三层结构
| 层 | 来源 | 内容 |
|---|---|---|
| 流程层 | 海报 | SA 售前 8 步（高层接触→沟通拜访→需求→方案设计→演示→拜访验证→报价→定价成单） |
| 弹药层 | 物料清单 10项+4补充 | 行业案例库 / 公司一页纸 / 定制方案模板 / 场景模块 / 会前调研表 / 业务场景包 / 故事模板 / Demo环境+脚本 / 异议Q&A / 商机质量评估表 + 产品库 / 客户情报 / 法务合同 / 报价评估体系 |
| 机制层 | 能力框架 10模块 | 统一物料库 / 影子导师制(Shadowing) / AI辅助工具 / 案例库更新机制 / 异议库扩充机制 |

## 2. 与已建系统的映射（落地关键）
- 物料 10项 ≈ fde-deployment 各阶段真实文件：`方案模板`→`spreadsheet-delivery`克隆；`Demo环境+脚本`→`ai-demo-builder`；`异议Q&A`→可沉淀成 skill
- 能力框架"案例库/异议库更新机制" = FDE 原则7（同问题下次别再需 FDE，变可复用系统）
- "AI辅助工具"模块 = 已建的 Hermes `fde-deployment` 编排层
- SA 8步每步加 FDE 红线 = skill 里"每步真实文件 + 现场闭环"

## 3. FDE vs SA 精确边界（来自 Palantir 官方定义）
- FDE：在客户现场**写生产代码** + 拥有"数据→决策"闭环（工程岗恰好客户-facing）
- SA/SE：演示产品后交专业服务（销售岗恰好技术）
- 本编排定位 = FDE，不是纯 SA：每阶段产出必须真实文件、可落地

## 4. FDE+SA 8 步协同流程（合并版，可直接用）
1. 高层接触 → FDE: 数字化阶段评估
2. 客户沟通/拜访 → FDE: 场景价值筛选（值得做>快速做）
3. 需求梳理 → FDE: 模糊想法变真问题
4. 方案设计 → FDE: 出架构图+方案文档（真实文件）
5. 方案演示 → FDE: Demo 原型（Cloudflare 隧道部署）
6. 拜访验证 → FDE: 进现场跟着干一遍
7. 报价 → FDE: 按模板中英文报价单
8. 最终定价成单 → FDE: 闭环回传 + Result Owner 兜底不丢结果

## 5. OCI 基础设施决策规则（FDE 栈相关）
- **负载均衡器（LB）何时用**：当前 OCI 免费机是**单机单实例**，且已用 Cloudflare 隧道做前端代理/SSL，**不用 LB**（CF 与 LB 功能重叠）。仅当出现**多后端（2+台机器）/高可用/多客户独立实例统一入口/统一 TLS**时才上（免费档 1 个 10Mbps LB 不花钱）。单机阶段别建，避免浪费额度+增复杂度。
- **存储必须自动挂载**：数据盘(OSS)缺失时优先修自动挂载（fstab `_netdev`+UUID / systemd 挂 OSS），**不能降级成"只同步不挂"**。见 `oci-ops-learnings.md`。
