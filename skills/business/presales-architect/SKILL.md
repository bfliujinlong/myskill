# 售前架构师（Pre-sales Architect）

## When to Use（何时使用）

- 客户提出需求/招标（RFP/RFQ），需要输出技术方案或投标文档
- 需要设计系统架构、画架构图、做技术选型对比
- 需要测算资源用量、给出报价依据、规划 POC/试点
- 需要把业务诉求翻译成技术语言，或反过来把技术能力讲成客户价值

## 标准工作流

### 1. 需求澄清（先问，再写）
用清单确认，避免凭空假设：
- 业务目标：客户要达成什么 KPI/解决什么痛点？
- 约束：预算区间、上线时间、合规（等保/数据出境）、现有系统/厂商锁定
- 规模：用户量、并发、数据量、地域
- 决策链：谁拍板、技术评委关心什么、商务评委关心什么

### 2. 方案设计框架（输出结构）
1. 业务理解与痛点共鸣（1 页）
2. 总体架构（分层：接入/应用/数据/基础设施）
3. 关键技术选型 + 对比表（自研 vs 开源 vs 云厂商，列优劣与成本）
4. 核心流程/时序图（关键场景）
5. 非功能设计：高可用、安全、可观测、灾备
6. 实施路径：里程碑、POC、灰度、上线
7. 价值量化：降本/增效/增收的粗略测算

### 3. 技术选型对比表模板

| 初期成本 | | | | |

### 4. 报价测算
- 一次性：实施人天 × 单价 + 软件授权
- 持续性：资源用量（CPU/存储/流量）× 单价 × 月数
- 留 15–20% 缓冲；区分「必选」「可选」让客户有取舍空间

### 5. 架构图
优先用 `creative/architecture-diagram` 技能生成深色主题 SVG 架构图；复杂流程用 `creative/excalidraw` 画时序/流程图。

### 6. 报价单文档生成（Word .docx，中英文各一份）
售前常需按客户/公司的**固定报价单模板**产出中英文两份。本会话验证可行的做法（不用手抄，用 python-docx 1:1 还原模板格式）：

**核心流程：**
1. **拿模板**：优先用客户/公司内部既有报价单 .xlsx/.docx（如安畅 SmartCare 报价单），用 `openpyxl`/`python-docx` 提取其表头结构（列名、合并单元格、字段顺序）。
2. **填数据**：用客户真实数据（迁移人天/单价、运维月费/年费、税率）填表。数字必须可溯源（人天×单价，或 SmartCare 标准价 ¥240/月·实例、¥2880/年·实例）。
3. **同时出中英文两份**：中文为主、英文版用专业术语（参考已有 Dubai Fintech 范本的英文措辞：Cloud Migration Engineer / Subscription-based / Exclusions 等）。
4. **生成**：用 python-docx 程序化生成两个 .docx，表头/样式对齐模板（蓝底白字表头、合并单元格、费用合计行）。

**SmartCare 报价单标准格式（安畅模板，已验证可 1:1 还原）：**
- 客户信息区：客户名称/联系人/电话/邮箱 + 客户经理/TAM/报价日期/有效期/付款周期/货币单位
- 迁移表（一次性）：序号/产品名称/产品详情/数量/税率/一次性单价/一次性小计/备注
- 运维表（SmartCare，周期性）：序号/产品名称/产品详情/数量/税率/一次性单价·小计/月度单价·小计/年度单价·小计/备注
- 计费规则明细（VM/PaaS/DB/容器/DevOps 各计费项）+ 服务级别（金1.2/银1.0/铜0.8）+ 特别说明（远程上浮20%、不含云资源费、30天有效等）

**小体量客户报价策略（中东迪拜新客户实践，2026-08-21 纪要）：**
- 不按官方刊例高基数报价；基于实际工作量核算，给「总价 + 最低价」双档供内部把控
- 迁移一次性费可控制在 $20k USD 以内；托管按单台资源量阶梯（$100/台/月，非阿里系中间件上浮10–15%）
- 轻量切入原则：报价过高直接流失新客户，先低门槛合作、随业务增长再调

**生成脚本骨架**见 `references/quotation-docx-template.md`（含 python-docx 表头/样式/中英文生成可复用片段）。

## 输出物清单
- 一页纸方案摘要（给老板/商务看）
- 技术方案正文（给技术评委看）
- 架构图（PNG/SVG）
- 选型对比表
- 报价单 + 实施计划

## 常见陷阱
- 过度设计：客户要 MVP，你给分布式微服务
- 只讲技术不讲价值：评委记不住你的架构，只记得你帮他省了钱
- 报价无依据：每个数字都要能溯源到人天或资源单价
- 忽略决策链：技术方案再好，拍板人关心的是风险和交付把握
