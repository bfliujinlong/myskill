# 项目经理（Project Manager）

## When to Use（何时使用）

- 启动新项目，需要拆 WBS、排期、定里程碑
- 需要周报/月报、风险登记、干系人沟通模板
- 跑敏捷：用户故事、迭代计划、看板、回顾
- 项目出现延期/范围蔓延，需要止血与重排

## 标准工作流

### 1. 启动：定目标与边界
- 一句话目标 + 成功标准（可量化）
- 范围：in scope / out of scope
- 关键干系人 + RACI（谁负责、谁批准、谁被告知）

### 2. 规划：WBS 与排期
WBS 拆解到「可估算、可分配、可验证」的颗粒度（通常 3–5 天一个 task）。
甘特图要素：任务、依赖、负责人、开始/结束、里程碑。

简易甘特（文本）：
```
W1  需求确认      [#####] 张三
W1-2 架构设计     [#####] 李四 依赖:需求
W3  开发          [########] 王五 依赖:架构
W5  测试+上线     [####] 全员
M   里程碑:上线评审
```

### 3. 执行：看板与站会
- 看板列：待办 / 进行中 / 待验证 / 完成
- 站会三问：昨天做了啥、今天做啥、卡点是什么
- 用 `xlsx` 或 `productivity` 相关技能维护任务表

### 4. 监控：风险与周报
风险登记册模板：
| 风险 | 概率 | 影响 | 应对 | 负责人 | 状态 |
|------|------|------|------|--------|------|
| | 高/中/低 | 高/中/低 | 规避/转移/接受 | | |

周报结构：
1. 本周进展（对照计划，完成/滞后）
2. 关键风险与阻塞
3. 下周计划
4. 需要决策/支持的事项

### 5. 收尾：复盘
- 目标达成度
- 做得好 / 待改进
- 沉淀的模板与文档

## 常见陷阱
- 排期不留缓冲（建议总工期 ×1.2–1.3）
- 范围蔓延不记录变更
- 风险等到爆发才说
- 周报只罗列任务不暴露卡点
