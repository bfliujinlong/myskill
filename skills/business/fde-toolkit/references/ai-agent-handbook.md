仓库本地克隆：`/data/skills-src/ai-agent-handbook`（留 .git，周更 `git pull`）。学习笔记：同目录 `_FDE学习笔记.md`。核心论断：**Agent = Model + Harness**，可靠性靠模型外的 harness 工程。

## 2026 调研数据（售前弹药，引用标注出处即可）

- 企业已开发 Agent 46%，但投产仅 18%；持续迭代 <10% → 「落地难」是普遍痛点，FDE 服务有市场。
- 架构：单 Agent 40% / Multi-Agent 42% / HITL 为主 15%。
- 采购：编码 Agent（Claude Code/Codex/Cursor/Qoder）57%；通用框架 78%；近 40% 两者都用。
- 建成后痛点：上下文/记忆管理需求 90%；**多模型路由+成本治理 63% 居网关能力之首**；评测/可观测 55% 靠人工，轨迹自动评测 <8%。
- 成功相关性：任务成功率 90%+ 的企业仅 ~10%；**有评测体系的团队成功率 70%+ 约为无评测的 2 倍**；持续迭代企业 84%。

话术模板：「阿里云白皮书调研显示，多模型路由+自动降级是 63% 企业最急需的网关能力——我们已经在单人环境跑通了 LiteLLM+model-router+token 监控这套，可以直接交付给客户。」
