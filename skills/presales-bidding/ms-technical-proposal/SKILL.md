# PCS Technical Proposal — 对外技术方案书

唯一目标：把 ms-service-solution 的六段工作稿 + 客户正式提交包，转成对外的投标技术方案书（分段生成章节 → 整合 → 四维自检）。**只写内容，不写格式**（格式归下游格式化/渲染环节）。

## 硬约束（违反即 BLOCK）

1. **数字只从「客户直源 / 待商务确认」取**——禁止新造；每个数字标源：`<客户文件>/<版本·日期>` 或 `待商务/客户确认`，二者必居其一；
2. **丰满 = 已确证事实的展开度**——叙事展开 How（流程/步骤/触发/责任人），展开不得引入无源数字；禁止为篇幅堆新事实；
3. **案例两段式**——①脱敏量化事实 ②「历史交付参考，不构成本项目 SLA/范围承诺」；
4. **图只画已锚定条目与已确证数字**——图是确证事实的可视化，不是新事实；
5. **内部痕迹不外泄**——纠错史、内部代号、KB 内部路径不进客户交付物；
6. **元规则**——每个"禁止"配一个"应当"，"应当"的产出锚定在"禁止"守护的事实上。

## 支持范围

**支持**：服务型项目（Managed Service / 云托管运维等）对外投标技术方案书。

**暂不支持**：格式转换（归下游格式化环节）、报价/SOW 内容（归 pricing/sow skill）、非服务型通用信息化方案。

## 执行步骤

### 步骤 0 — 前置检查（强制）

Read `project.yaml`：存在→继续；否则 `BLOCKED: 当前目录不是已初始化的 PCS Project`。

### 步骤 0.5 — 素材加载（只读，显式）

- **产出前先读契约**：`references/output-template.md` 的「丰满度底线（L1 骨架契约）」+ `references/contract.json` 的 `granularity_contract`——先确立"丰满=展开度、每章 How、禁止清单"，再动笔；
- 上游：ms-service-solution 的六段工作稿（`03_方案与应答/01_服务方案/01_共通设计/`）——**范围锚定结论 + SLA 有源值 + RACI 的权威源**；
- 提交包（外部/人工前置产物，可选）：`03_方案与应答/05_客户正式提交包/`（Service Catalog / SLA 表 / 团队画像 / 交接清单 / 报告清单）——已放入则读取为佐证源，**未放入 → WARN 并标"待补充"，不阻断分段生成**；
- KB 素材键（显式注入）：`company_intro`（公司介绍/资质）、`bid_chapters`（投标章节素材）、`architecture_images`（架构图）、`case_index`（案例佐证）；
- **未注入的素材键** → WARN 并标"待补充"，不虚构。

### 步骤 1 — 分段生成章节

按 `references/output-template.md` 的章节模板，逐章生成独立文件：

```
03_方案与应答/01_服务方案/技术方案/[项目]/01_公司介绍与项目理解.md
… 09_云厂商合作与持续演进.md
附录A_RFP追溯矩阵.md / 附录B_覆盖率自检.md
```

- 每章强制引用 service-solution 的锚定结论，数字只从「客户直源 / 待确认」取；
- 章节可并发生成（每章上下文独立，仅依赖上游工作稿，不依赖其他章）；
- 每章生成后跑「丰满度自检」：叙事展开 How 了吗？展开引入新数字了吗？新数字标源了吗？

### 步骤 2 — 整合

```bash
python3 scripts/merge_chapters.py --dir 03_方案与应答/01_服务方案/技术方案/[项目]/ \
    --output 03_方案与应答/01_服务方案/对外技术方案书-[项目]-v1.0.md \
    --strict --rfp-count [R]
```

整合脚本：按序合并 01~09 + 附录 → 生成目录 → **四维门禁（--strict 下不达标 exit 2 BLOCK）** → 交叉引用检查（SLA 条目数 / 目录条目数 / 角色数与上游一致）。**产出后必过卡尺**：任一维度 GATE-FAIL 回补对应章节后重跑，不静默通过。

### 步骤 3 — 四维自检（输出，作为方案内附录B）

```
In-Scope 项数: N ｜ 有目录映射: x/N ｜ 有案例佐证: y/N
RFP 追溯率: z/R（R1-Rn 全量有章节落点）
叙事完整度: 每个 In-Scope 域有 How 流程叙述
图示: 组织架构图 / 告警链路 / 交接时间轴（关键图覆盖）
```

任一维度不达标 → 回补对应章节，不静默通过。

## 输出

- `03_方案与应答/01_服务方案/技术方案/[项目]/01~09 章 + 附录`（分段稿，可并发）
- `03_方案与应答/01_服务方案/对外技术方案书-[项目]-v1.0.md`（整合稿）
- 整合稿交下游格式化/渲染环节品牌化 → docx

## Pitfalls

- **数字零容忍自造**：对外交付物，任何无源数字即 BLOCK；
- **不写格式**：本文只产 md 内容，封面/页眉/表格样式归下游格式化环节；
- **不改上游结论**：与 service-solution 冲突时，回上游改，不静默覆盖；
- **丰满不是加节**：每个域的展开度，不是章节数；禁止为篇幅加节。
