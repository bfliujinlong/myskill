## 硬约束速查

1. 数字只从「客户直源 / 待商务确认」取，标源；
2. 丰满 = 已确证事实的展开度，不引入无源数字；
3. 案例两段式；
4. 图只画已锚定条目与已确证数字；
5. 内部痕迹不外泄。

## 丰满度底线（L1 骨架契约）

> 每章「丰满」= 已确证事实的**展开度**，可度量、可自检；不是新数字堆砌，也不是页数。产出前读本契约，产出后过 merge 卡尺。

| 维度 | 底线（每个 In-Scope 域） | 卡尺（merge_chapters 检测） |
|---|---|---|
| 叙事展开 How | 01-09 每章≥1 处流程/步骤/触发/责任人/时序叙述 | 逐章叙事检测，缺章 GATE-FAIL |
| 目录映射 | In-Scope 项到 Service Catalog 母版有反查映射（主/支撑标注） | 映射提及≥1 |
| 案例佐证 | 有接管/同类域时，两段式佐证（脱敏事实 + 不构成本项目承诺） | 佐证提及≥1 |
| RFP 追溯 | 附录A 每条 R1-Rn 有章节落点 | 追溯行 z/R，`--rfp-count` 下须=R |
| 图示 | 组织架构 / 告警链路 / 交接时间轴 关键图覆盖 | 图示符号计数 |

**展开动作（应当）**：把一个确证事实展开为 What→Why→How→Who→When 的叙述与流程，而非并列更多 bullet。
**反面（禁止）**：为篇幅加节 / 加无源数字 / 案例整包搬运 / 母版全量抄入 / 佐证改写成承诺。

**门禁口径**：对外交付前必须 `merge_chapters.py --strict [--rfp-count R]` 跑通（四维 PASS），任一维度 GATE-FAIL 回补对应章节，不静默通过。
