# 适配点（服务型特化）

> ms-technical-proposal 在服务型项目上的适配点，与通用信息化投标方案的区别。

## A. 章节结构适配

| 通用信息化（pre-sale-plugin 参照） | 服务型（pcs 本 skill） |
|---|---|
| 功能设计 / 系统架构 | Service Catalog 四档 + RACI（02） |
| 性能指标 | SLA/SLO 45 项 + 事件/问题/变更/监控（03） |
| 实施计划 | Mobilization 双轨交接 + 门禁（05） |
| 售后服务 | 运营治理 + CSI 闭环（08/07） |

## B. 数字纪律适配（服务型特有）

- SLA 数字 = 客户 RFP 模板 + PART D 直源，不自造；
- DR = SLO（仅报告，不触发 Credit）；
- 服务目录条目数与 4-A xlsx 实数核平；
- 角色画像人数/姓名留 TBA（报价轮定编）。

## C. 丰满度档位（可调）

| 档位 | 叙事深度 |
|---|---|
| 标准 | 每个 In-Scope 域有 How 流程（本 skill 默认底线） |
| 增强 | 每个 How 再展开到可执行步骤级（如 War Room T+0/T+15/T+30） |

## D. 与上游 skill 的边界

- 不重复 service-solution 的六段拆分（那是内部纪律结构）；
- 不改上游范围锚定结论，冲突回上游；
- 不产格式（封面/表格样式归下游格式化环节）。
