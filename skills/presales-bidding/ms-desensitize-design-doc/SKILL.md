# HLD/LLD 设计文档脱敏 Skill

## 概述

对 HLD（High-Level Design）和 LLD（Low-Level Design）设计文档执行脱敏处理。

**特殊挑战**：设计文档包含大量技术细节——网络拓扑、IP 规划、主机名规则、配置参数、安全策略——这些既是标识符泄露的重灾区，又是方案参考价值的核心。

**核心原则**：脱敏标识符，保留信息。架构设计思路、容量规划方法、安全分层策略必须完整保留。

## 前置检查

1. 确认源文件位于 L2 区
2. 确认目标目录为 L1 区
3. 读取源目录和目标目录的 `.kb-policy.yaml`
4. 判断文档格式：Markdown 还是 Word
5. 判断文档类型：HLD（概要设计）还是 LLD（详细设计）

## HLD vs LLD 脱敏差异

| 维度 | HLD（概要设计） | LLD（详细设计） |
|------|----------------|----------------|
| IP 地址 | 通常不含具体 IP，含网段规划 | 含具体 IP 分配 |
| 主机名 | 含角色命名规则 | 含具体主机名 |
| 配置参数 | 含参数模板 | 含具体配置值 |
| 架构图 | 逻辑架构图 | 物理部署图 |
| 安全策略 | 安全分层描述 | 具体 ACL/防火墙规则 |
| 脱敏重点 | 客户名、项目名 | IP、主机名、凭据、域名 |

## 执行步骤

### 步骤 1：读取设计文档

根据文档格式选择读取方式：
- Markdown → 直接读取文本
- Word → 使用 python-docx 读取

### 步骤 2：执行基础脱敏

使用共享脱敏引擎处理所有文本：

```python
from desensitize_engine import DesensitizeEngine
engine = DesensitizeEngine()
result = engine.process_text(text)
```

### 步骤 3：设计文档特有处理

#### 3.1 网络拓扑/IP 规划

| 原始内容 | 脱敏方式 | 示例 |
|---------|---------|------|
| 具体 IP 地址 | `[REDACTED-IP]` | `172.22.2.9` → `[REDACTED-IP]` |
| 网段规划 | 保留结构，替换网段 | `172.22.0.0/16` → `10.0.0.0/16` |
| VLAN ID | 保留（不含客户标识） | `VLAN 100` → 保留 |
| 子网掩码 | 保留 | `/24` → 保留 |

#### 3.2 主机名/实例名

| 原始内容 | 脱敏方式 | 示例 |
|---------|---------|------|
| 含客户标识的主机名 | 角色化名称 | `CVM-WN-KQ` → `CVM-WEB-01` |
| 含环境标识的主机名 | 环境-角色-序号 | `PRD-PBM-堡垒机` → `PRD-BASTION-01` |
| 命名规则描述 | 保留规则，替换示例 | `CVM-{环境}-{角色}` → 保留 |

#### 3.3 配置参数/代码块

| 原始内容 | 脱敏方式 |
|---------|---------|
| 配置文件中的 IP | `[REDACTED-IP]` |
| 配置文件中的域名 | `[REDACTED-DOMAIN]` |
| 配置文件中的凭据 | `[REDACTED]` |
| 配置文件中的端口 | 保留（不含客户标识） |
| 配置文件中的路径 | 保留（不含客户标识） |
| 配置文件中的参数值 | 保留（不含客户标识） |

#### 3.4 架构图描述

| 原始内容 | 脱敏方式 |
|---------|---------|
| 架构图中的客户名 | 替换为代号 |
| 架构图中的 IP | `[REDACTED-IP]` |
| 架构图中的主机名 | 角色化名称 |
| 架构图的分层结构 | **保留** |
| 架构图的组件关系 | **保留** |
| 架构图的流量走向 | **保留** |

#### 3.5 安全策略

| 原始内容 | 脱敏方式 |
|---------|---------|
| ACL 规则中的 IP | `[REDACTED-IP]` |
| 防火墙规则中的端口 | 保留 |
| 安全组规则中的 CIDR | 替换为示例网段 |
| 漏洞扫描结果 | 泛化（保留类型，去除路径） |
| 渗透测试报告 | 泛化（保留方法，去除细节） |

### 步骤 4：验证

- 确认无真实客户名残留
- 确认无真实 IP 残留（示例网段除外）
- 确认无凭据残留
- 确认架构设计思路完整保留
- 确认容量规划数据完整保留
- 确认安全分层策略完整保留

### 步骤 5：重命名输出文件

按命名规范：`主题-客户代号-脱敏.md` 或 `主题-客户代号-脱敏.docx`

## 设计文档特有注意事项

1. **网段规划保留结构**：`172.22.0.0/16` 替换为 `10.0.0.0/16`，保留子网划分结构
2. **命名规则保留**：主机名命名规则（如 `CVM-{环境}-{角色}`）是重要设计决策，必须保留
3. **容量规划保留**：资源规格（CPU/内存/磁盘）是核心设计数据，必须保留
4. **安全分层保留**：安全分层策略（如 DMZ/内网/管理网）是架构核心，必须保留
5. **代码块不豁免**：设计文档中的配置代码块同样需要脱敏
6. **架构图图片**：如果架构图是图片，无法直接脱敏，需要人工审核或重新绘制
