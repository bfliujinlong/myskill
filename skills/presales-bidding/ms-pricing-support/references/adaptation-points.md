# 适配点清单（动态框架）— ms-pricing-support / references/adaptation-points.md

> **定位**：本清单是报价测算框架的**可调参数层**。任意 Managed Service Bidding 项目来了，
> skill 先读上游（服务方案范围 + 显式报价参数），对每个适配点**识别客户诉求 → 选档 → 填入框架占位符**。
> 每个适配点给：**默认档** / **调整依据（看哪个上游信号）** / **示例取值（reference-only）**。
> 示例列仅供对照，**不是默认值**——它只是"其中一种取法"。
>
> ⚠️ **确定性纪律不参与适配**：所有具体金额/单价始终来自显式输入 + `compute_pricing.py`。
> 本清单调整的是**报价的结构形态**（怎么计费、按什么分档），**不是**价格数字本身。

## 选档纪律（普适，不变）

1. **默认档不等于示例档**：默认取"最常见的 Managed Service 报价形态"，示例只是被验证过的一组值。
2. **每个选档挂上游依据**：选了哪档，必须能指向 RFP§ 或服务方案§ 的信号，不凭空选。
3. **无信号→保守档 + 标待确认**：上游没给信号的适配点（如税率、结算机制），取"待商务及客户确认"，不自行拔高。
4. **确定性纪律不参与适配**：所有金额来自显式输入 + 脚本；不推断单价、不套默认价目、不引模型估算——任何客户都不可调。
5. **数量三分不可调**：Baseline / pricing_basis / 客户确认 三者始终区分，报价数不升级为确认数——任何客户都不可调。
6. **新客户新维度**：若出现清单未覆盖的报价形态（如混合云分账、跨境结算），先在报价表显性标注，事后回补本清单。

## 如何扩展本清单

本清单以一组**示例取值**作为参考建立。每新做一个 Managed Service 项目：
- 若出现新的报价形态维度 → 增行，补默认档 + 调整依据；
- 若某档位取值范围变化 → 更新档位说明；
- **示例列永远只是 ref-only 对照**，不随新项目改写。
