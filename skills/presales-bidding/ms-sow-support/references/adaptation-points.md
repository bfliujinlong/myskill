# 适配点清单（动态框架）— ms-sow-support / references/adaptation-points.md

> **定位**：本清单是 SOW 框架的**可调参数层**。任意 Managed Service Bidding 项目来了，
> skill 先读上游（服务方案 + 报价测算），对每个适配点**识别客户诉求 → 选档 → 填入框架占位符**。
> 每个适配点给：**默认档** / **调整依据（看哪个上游信号）** / **示例取值（reference-only）**。
> 示例列仅供对照，**不是默认值**——它只是"其中一种取法"。
>
> ⚠️ **范围守恒与数量三分纪律不参与适配**：SOW 范围 ⊆ 方案、金额引用报价、数量三分——任何客户都不可调。
> SOW 是**汇总型** skill，绝大多数内容来自上游工件；适配点仅调整**呈现结构**，不新增任何内容。

## 选档纪律（普适，不变）

1. **默认档不等于示例档**：默认取"最常见的 SOW 汇总结构"，示例只是被验证过的一组值。
2. **一切来自上游**：SOW 不产生新内容，所有适配点取值都必须能追溯到服务方案或报价测算工件。
3. **范围守恒不参与适配**：SOW 范围 ⊆ 方案 In Scope、金额引用报价、数量三分——任何客户都不可调。
4. **未确认不固化**：RACI/验收/里程碑未明确前进"待确认"分区，不因客户"想要干净合同"而升级。
5. **一致性不抹平**：上游数量/频率冲突保留差异并 BLOCKED/警告，不静默修正。
6. **新客户新维度**：若出现清单未覆盖的 SOW 结构维度，先在 SOW 显性标注，事后回补本清单。

## 如何扩展本清单

本清单以一组**示例取值**作为参考建立。每新做一个 Managed Service 项目：
- 若出现新的 SOW 结构维度（如按批次交付、跨区域范围）→ 增行，补默认档 + 调整依据；
- **示例列永远只是 ref-only 对照**，不随新项目改写。
